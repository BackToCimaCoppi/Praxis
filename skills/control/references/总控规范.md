# 总控规范

本文档是 control skill 和 task-control-doc skill 的**唯一规范真值源**（用户级 / 跨项目通用）。

任何与生命周期、归档、目录结构相关的规则只在本文件维护。两个协同 skill 都从这里引用，不再各自重写。

---

## 1. 目录结构

```text
<PROJECT_ROOT>/docs/00-任务总控/
├── README.md                                  # 活跃任务索引（仅入口/导航）
├── {YYYY-MM-DD}-{任务名}/                      # 活跃任务子目录
│   ├── README.md                              # 主总控（拆分 / 单文件统一为 README.md）
│   ├── T1-{子任务名}.md                        # 仅拆分模式存在（脚本硬依赖前缀）
│   ├── T2-{子任务名}.md
│   └── _shared/                               # 唯一过程资产目录（归属由文件名前缀区分）
│       ├── T{n}-{资产名}.md                    # 子任务专属资产
│       ├── T{n}-{资产名}/                      # 子任务多文件资产（图片包等）
│       └── {资产名}.md                         # 任务级共享资产（无前缀）
└── 归档/
    ├── README.md                              # 归档总索引
    └── V{x}/
        ├── README.md                          # 版本归档索引
        └── {YYYY-MM-DD}-{历史任务名}/           # 整体迁移过来（含 _shared/；旧任务可能含历史 _T{n}/）
```

### 1.1 放置规则

- 一个总控任务 = 一个独立子目录，根目录不直接堆放任务文件
- 与该总控强相关的人工执行清单、指南、总结，可放在同任务目录下
- 项目级正式资产（接口测试脚本、手工联调手册、长期测试基座）落到项目自身约定位置（如 `docs/04-...` / `tests/`），**不长期放在总控目录**
- 已完成任务进归档；已删除任务直接删除（不进归档）
- 顶层 `README.md` 只做活跃任务索引，不承载某个任务的细节正文

### 1.1.1 过程资产放置规则（任务执行过程中产生的临时文档）

总控任务执行过程中常产生**仅服务于本任务、不进入项目正式文档体系**的中间文档（设计稿、数据样本、批判稿、清单、原型等）。这类资产**全部放进唯一资产目录 `_shared/`**，归属由**文件名前缀**区分，不再按目录区分：

| 资产归属 | 命名 | 示例 |
|---------|------|------|
| 某子任务专属 / 产出 | `T{n}-{资产名}.md` | `T2-模型能力调查.md`、`T9-对抗评审报告.md` |
| 二级子任务产出 | `T{n}.{m}-{资产名}.md` | `T6.3-联调记录.md` |
| 多文件资产（图片包、样本集等） | `T{n}-{资产名}/` 子目录 | `T8-渲染样图/` |
| 任务级共享（无单一子任务归属：需求真值、对话沉淀、跨子任务定稿） | 无前缀自然中文名 | `需求真值.md` |
| 进入项目正式文档体系的产出 | 项目本地约定位置（如 `docs/0x-.../...md`），不放 `_shared/` | 遵守项目自身命名规则 |

**判定口诀**：这个文件能填进某个 T{n} 的「输出物」字段吗？能 → 带 `T{n}-` 前缀；不能（任务级）→ 无前缀。

**高频资产标准名**（同类资产只许一个名字，不得自创变体）：
`T{n}-轻量设计方案.md` / `T{n}-施工蓝图.md` / `T{n}-蓝图评审报告.md` / `T{n}-对抗评审报告.md`

**硬约束**：
- 资产目录只有 `_shared/` 一个，以 `_` 开头（脚本只在任务根目录一层 glob `T{n}-*.md` 定位子任务工作包，不进 `_shared/`，因此资产文件带 `T{n}-` 前缀不会与脚本撞车）
- **禁止**在任务根目录平铺资产；**禁止**新建 `_T{n}/` 目录（旧规则已废除；存量任务的 `_T{n}/` 原地只读，不迁移）
- 即使只有 1 个资产也建 `_shared/`，规则一致优先于轻量

**资产 ↔ 子任务字段对齐**：
- 所有资产路径必须显式列在对应子任务详情的「输出物」字段（输出物 = 这个子任务交付了什么，不区分正式 / 过程资产），路径统一写 `_shared/...`
- 总控主文件**不**单独维护「资产清单」章节——「输出物」字段已是真值源，不重复登记

**生命周期**：
- 资产随任务目录一起进归档（`归档/V{x}/{任务名}/_shared/...`），归档脚本不裁剪
- 任务被删除时，资产随目录一起删除（不进归档）

### 1.2 命名规则

- **任务子目录**：`{YYYY-MM-DD}-{中文任务名}/`
  - `YYYY-MM-DD` 是任务**创建日**（创建后不变，避免改名）
  - 日期前缀防多 worktree 编号撞车——日级粒度下天然唯一
  - 极端情况（同日创建多任务）：加字母后缀 `2026-05-10b-...` 或加时分 `2026-05-10-1430-...`
- **主总控文档**：`README.md`（无论拆分 / 单文件模式都是这个名字）
- **拆分子任务文件**：`T{n}-{中文子任务名}.md`，`n` 从 1 开始递增，**仅在任务内部唯一**
- **归档版本目录**：用主产品迭代名（`V1` / `V2` / ...）；跨版本任务按主版本归档，覆盖范围写在归档索引里
- **README**：每个能列索引的目录（顶层 / 归档 / 归档/V{x}）放一个 `README.md`，不带前缀

### 1.2.1 二级任务（中途拆分支持）

> 触发场景：执行过程中发现某个一级父任务 Tn 工作量超出预期，需要原地拆为 Tn.1 ~ Tn.N 二级子任务继续推进。

**只允许两级**。`Tn.x` 不能再拆。深层拆分要么开新总控、要么改设计。

**编号格式**：

- 一级：`T1`、`T2`、`T3` …（仅数字）
- 二级：`T1.1`、`T1.2`、`T1.3` …（父编号 + 点 + 数字）

**状态语义**：

| 角色 | 状态列写法 | 派生方式 |
|------|----------|---------|
| 普通叶子任务（Tn 无子） | 用户手填 `待完成` / `进行中` / `已完成` / `阻塞` / `已取消` | 真值源 |
| 二级子任务（Tn.x） | 同上 | 真值源 |
| 父任务（Tn 有子） | 固定占位 `派生` | 脚本从直接子任务聚合：阻塞 > 进行中 > 未启动 > 已完成 |

**依赖语义**：

- 依赖列写一级编号 `T1`：若 T1 是父，自动展开为"所有 T1.* 完成"才算满足；若 T1 是叶子，直接判 T1 状态
- 依赖列写二级编号 `T1.2`：精确依赖该叶子的状态
- 拆分时**不**自动改其他任务对原 Tn 的依赖引用——语义自动扩展为"所有 Tn.* 完成"

**文件布局**（拆分模式下，单文件模式不涉及文件迁移）：

- 原 `T{n}-{子任务名}.md` → 拆分后迁移到 `T{n}/T{n}.md`（保留背景/范围作为父任务说明）
- 二级子任务 → `T{n}/T{n}.{m}-{子任务名}.md`
- 脚本（render / next_subtask / archive / split）通过 `find_subtask_md()` 统一定位文件

**脚本对父任务的处理**：

- `render_control_status.py`：父行状态列渲染为 `<派生值>（派生）`，叶子计数排除父
- `next_subtask.py`：永不推荐父任务；依赖判定时父展开为所有直接子
- `archive_control.py`：归档校验跳过派生父，只看叶子全为 `已完成` / `已取消`
- `split_subtask.py`：用户显式触发；拒绝深层拆、拒绝重复拆、拒绝拆已完成/已取消任务

详细执行流程见 control skill 的 §5.5。

---

### 1.3 单文件 vs 拆分

| 维度 | 单文件 | 拆分 |
|------|------|------|
| 主总控 | `README.md`（含全部子任务详情） | `README.md`（仅含子任务总表 + 进展记录） + `T{n}-...md`（独立子任务工作包） |
| 适用 | 3-7 个子任务、各子任务详情不超过 50 行 | 8+ 个子任务、单子任务详情很长 |

**默认用单文件**。`README.md` 整文件超过 400 行 → 考虑拆分。

## 2. 任务生命周期

### 2.1 创建阶段

1. 在 `<PROJECT_ROOT>/docs/00-任务总控/` 下新建任务目录 `{YYYY-MM-DD}-{任务名}/`
2. 用 `task-control-doc` skill 创建 `README.md`（基于 `assets/任务总控模板.md` 或拆分模板）
3. 在顶层 `README.md` 的「当前活跃任务」表格新增一行
4. 若需要独立 worktree：手动 `git worktree add`，命名遵循 §3.1（不需要在文档里登记）

### 2.2 推进阶段

- 通过 `/control` 进入并执行子任务
- 子任务开始时改 `进行中`，完成时改 `已完成`，遇阻改 `阻塞` 并写明原因
- 在哪个 worktree 写代码由 `git worktree list` 真值决定；命名约定便于人眼识别，但 worktree 不绑定任务，任意 worktree 都可以切换激活总控
- 多激活时通过 `set_active.py` 写入 `.claude/local/active-control` 选择默认总控（详见 §3.4）
- 模型选择由用户在会话开头自行决定（用 `/model` 命令切换）

### 2.3 完成与归档

任务整体完成后，**必须按以下顺序**执行（推荐用 `archive_control.py` 自动完成）：

1. 回填所有子任务状态、输出物和进展记录
2. 从顶层 `README.md` 的「当前活跃任务」删除该任务行
3. 迁移整个任务目录到 `归档/V{x}/{YYYY-MM-DD}-{任务名}/`
4. 在 `归档/README.md` 增加该任务的归档登记
5. 在 `归档/V{x}/README.md` 增加该任务的版本登记
6. 若该任务有专属 git worktree：`git worktree remove` 并删除分支（手动）

### 2.4 删除阶段

任务被明确放弃 / 不做时：

1. 删除整个任务目录
2. 从顶层 `README.md` 移除条目
3. 若有专属 git worktree：手动 `git worktree remove` 并删除分支
4. **不进归档**

## 3. Git Worktree 路径规范

> 仅约束 worktree 的**物理路径和命名**，不维护任何文档绑定。

### 3.1 路径格式

Worktree 必须放在主仓库的**兄弟目录**位置，命名为 `{REPO_NAME}--{任务关键词}`（英文短语，便于人眼识别）。

```text
{PARENT_DIR}/                        # 与主仓库同级父目录
├── {REPO_NAME}/                     # 主仓库
├── {REPO_NAME}--share-refactor/     # ✅ 任务 worktree
└── {REPO_NAME}--admin-dashboard/    # ✅ 任务 worktree
```

**命名约定的作用**：仅为人类可读性建议——从 worktree 路径名可以一眼看出对应任务。**脚本不读 worktree 名字**，多激活时通过 `.claude/local/active-control` 文件显式选择（§3.4）。

### 3.2 禁止位置

| 禁止路径 | 为什么禁止 |
|---------|----------|
| `<PROJECT_ROOT>/.claude/worktrees/xxx` | 嵌套主仓库内部，污染 git status，AI 搜代码时混淆两个分支 |
| `<PROJECT_ROOT>/任何子目录/xxx` | 同上，只要在主仓库目录内部就一律禁止 |
| `~/.claude/worktrees/xxx` | 与项目失去归属关系 |
| `{PARENT_DIR}/{REPO_NAME}-xxx`（单横线） | 命名不符规范，会与普通项目名混淆 |

### 3.3 创建命令模板

```bash
REPO_ROOT=$(git rev-parse --show-toplevel)
PARENT_DIR=$(dirname "$REPO_ROOT")
REPO_NAME=$(basename "$REPO_ROOT")
TASK_KEYWORD="share-refactor"   # 任务英文关键词
WORKTREE_PATH="$PARENT_DIR/$REPO_NAME--$TASK_KEYWORD"

git worktree add "$WORKTREE_PATH" -b "feature/$TASK_KEYWORD"
git worktree list   # 验证：路径应在兄弟目录，而非主仓库内部
```

### 3.4 真值源与激活配置

- **当前 worktree 与分支**：`git worktree list` / `git branch --show-current`
- **任务 ↔ worktree 对应关系**：用户自行管理（命名约定 §3.1 仅供人眼识别，脚本不读）
- **当前 worktree 默认激活总控**：`<PROJECT_ROOT>/.claude/local/active-control`
  - 不进版本控制（`.gitignore` 排除整个 `.claude/local/` 目录）
  - 每个 worktree 物理目录独立，互不影响、永不冲突
  - 仅在多激活总控时生效：唯一总控时此配置无意义
  - 通过 `set_active.py <关键词>` / `--clear` / `--show` 管理
  - 文件格式：单行任务目录精确名（如 `2026-01-01-示例域重构`）
- 不维护任何独立的"工作区映射表"或"工作区绑定.md"文档

## 4. 执行边界（红线）

> 这是 `/control` 执行子任务时的**最高优先级约束**，所有 skill 都必须遵守。

### 4.1 单子任务边界

- 用户指定 `/control <key> Tn` → **只动 Tn**，不要顺手做 Tn-1 或 Tn+1
- 子任务的「输出物」全部产出 → **立刻停止**，回填总控状态，等用户下一步指令
- ✅ 允许：读其他子任务的产出物（依赖关系决定）
- ❌ 禁止：写入其他子任务范围（即使发现"可以顺便做"）

### 4.2 子任务详情即工作包

- 每个子任务详情应该是一个**自包含的工作包**：包含背景、强制阅读、要做什么、不做什么、输出物、完成判定
- 新会话执行时，**只读子任务详情和它列出的强制阅读文件**，不读其他子任务详情
- 详见 `task-control-doc` skill 的子任务详情结构

### 4.3 派给外部 agent 时

派 ask-sonnet / ask-opus / 其他 skill 时，必须在 prompt 里注入：

> 你只执行编号 `T<n>` 的子任务，**不要**接管任务调度，**不要**做其他子任务。
> 禁止读取或调用 `~/.claude/skills/control/`、本规范文件。

## 5. 归档索引同步表

总控生命周期内涉及 3 处索引文件，每个事件需要同步的目标如下：

| 事件 | 顶层 README | 归档/README | 归档/V{x}/README | 备注 |
|------|:---:|:---:|:---:|------|
| 创建任务 | ➕ 新增行 | — | — | 新增活跃任务索引 |
| 子任务推进 | — | — | — | 仅在状态变化时改任务总控本身 |
| 任务归档 | ❌ 删除行 | ➕ 登记 | ➕ 登记 | 3 处全动 |
| 任务删除 | ❌ 删除行 | — | — | 不入归档 |

**重要**：归档涉及 3 处同步，建议用 `archive_control.py` 自动完成。

## 6. 强制阅读优先级（按粒度递增）

`/control` 的强制阅读**严格按粒度递增**，避免铺垫挤占上下文：

| 触发模式 | 必读文件 |
|---------|---------|
| `/control init` | 无（直接调脚本） |
| `/control list` | 顶层 README.md |
| `/control <关键词>` | 上 + 主总控 README 的「任务背景」「子任务总表」（不读完整详情） |
| `/control <关键词> Tn` | 上 + Tn 子任务详情 + Tn「强制阅读」列出的文件 |
| 创建新总控 | 本规范 + task-control-doc skill |
| 归档任务 | 本规范（§2.3 流程）+ 归档目录索引 |

`CLAUDE.md` 由会话级注入，不需要在 control 里再读。

本规范从"每次必读"降为"按需查阅"——只在创建新总控、归档、或对规则有疑问时读。

---

## 7. 真值优先级

当本规范与某个 skill 文档冲突时，**以本文件为准**。skill 应该被改回与本文件一致。

git 自身（`git worktree list`、`git branch --show-current`、`git status`）是 worktree 状态的唯一真值源；任何文档**不**镜像它。

## 8. 自动化脚本

| 脚本 | 用途 |
|------|------|
| `~/.claude/skills/control/scripts/bootstrap_project.py` | 新项目首次初始化（建 docs/00-任务总控/ 骨架，幂等） |
| `~/.claude/skills/control/scripts/render_control_status.py` | 渲染指定总控的状态表（只读） |
| `~/.claude/skills/control/scripts/next_subtask.py` | 输出下一个可执行子任务（依赖已满足、状态为 `进行中` 或 `待完成`） |
| `~/.claude/skills/control/scripts/list_blocked.py` | 列出所有活跃总控中状态为 `阻塞` 的子任务 |
| `~/.claude/skills/control/scripts/set_active.py` | 管理当前 worktree 的激活总控配置（写/清/查 `.claude/local/active-control`） |
| `~/.claude/skills/control/scripts/archive_control.py` | 归档总控时自动同步 3 处索引并迁移目录到 `归档/V{x}/` |
| `~/.claude/skills/control/scripts/split_subtask.py` | 把一级父任务 Tn 拆为二级子任务 Tn.1 ~ Tn.N（详见 §1.2.1） |

详细参数和示例见各脚本 `--help`。
