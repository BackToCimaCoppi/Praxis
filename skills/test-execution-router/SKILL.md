# 测试执行路由

本 skill 只回答：冻结用例如何被执行、路由到哪里、结果如何收口。不要在本层改用例口径；不要写项目凭据或平台专属细节。

## 0. 硬门

执行前必须满足：

- 已读取冻结用例规格。
- 已确认 `execution_ref` 或预定锚点。
- 已生成测试执行矩阵。
- 已识别项目执行 skill；如果项目没有执行 skill，先报告缺口。

禁止行为：

- 边执行边修改断言。
- 用“环境不方便”跳过自动化。
- 把手工验证计作自动化覆盖。
- 失败后只写“测试失败”，不分类。

## 1. 执行流程

1. 读取冻结用例规格与测试矩阵。
2. 校验每条用例的来源、数据策略、自动化方式、`execution_ref`。
3. 生成执行矩阵：测试面、执行顺序、所需数据、证据路径、阻断条件。
4. 路由到项目执行 skill 的对应参考文件。
5. 执行或实现测试资产。
6. 编号覆盖核对：冻结 `assertion_index` 的每个 `AC-x` 都在测试资产里有字面落点（标注格式见 `test-case-design §2.1`）；项目提供编号覆盖检查器命令的必须跑检查器，没有的必须人工产出逐条对账表。有编号无落点 = 阻断。
7. 收集证据：命令/工具、结果、截图/日志、DB 终态、失败分类。
8. 产出执行报告；未通过项必须给下一步处置。

## 2. 路由表

| 用例类型 | 路由 |
|---|---|
| 单元测试 | 项目执行 skill 的 unit 参考 |
| 接口测试 | 项目执行 skill 的 api 参考 |
| DB 预置/校验 | 项目执行 skill 的 db 参考 |
| Web UI 自动化 | 项目执行 skill 的 web-ui 参考 |
| 小程序 UI 自动化 | 项目执行 skill 的 mp-ui 参考 |
| 视觉/VLM 验收 | 项目执行 skill 的 visual 参考 |
| 交付/发布验证 | 项目执行 skill 的 release/evidence 参考 |
| 手工验证 | 项目执行 skill 的 evidence 参考；只生成 runbook 与回传要求 |

项目执行 skill 的名称、参考文件布局与命令细节由**项目级补丁**声明（见 `templates/项目级补丁模板/`）。项目一旦提供了自己的测试执行 skill，该项目的全部执行请求统一路由到它，本 skill 不再猜测命令。

## 3. 执行顺序

默认顺序：

1. 静态/单元测试：快速暴露局部缺陷。
2. 数据前置：准备幂等测试数据。
3. 接口测试：验证契约与业务写链路。
4. DB 校验：验证终态、不变量、幂等。
5. Web/小程序 UI 自动化：验证用户路径。
6. 视觉验收：判读布局、图表、canvas、示例内容等视觉结果。
7. 交付收口：汇总证据和阻断项。

可以调整顺序，但必须说明原因。例如 UI 用例依赖接口造数完成，接口测试必须先跑。

## 4. 失败分类

失败必须分类：

| 分类 | 含义 | 处置 |
|---|---|---|
| `PRODUCT_BUG` | 产品实现与冻结用例或上游真值不符 | 修产品代码，重跑相关测试 |
| `TEST_BUG` | 执行脚本错误，但用例口径正确 | 修脚本，不改用例断言 |
| `SPEC_STALE` | 上游真值已变，用例过期 | 非 goal 态：停机请求人工裁决，更新冻结记录；**goal 执行态：规格刚冻结即过期 ≈ 规格错了，走章程回炉出口**（本次 goal 作废退回设计步），不原地停机等待 |
| `ENV` | 服务、网络、账号、依赖、测试数据环境问题 | 修环境或重建数据后重跑 |
| `FLAKE` | 时序或异步导致间歇失败 | 修等待/隔离；连续 flake 不得当通过 |
| `MANUAL_REQUIRED` | 工具确实无法自动化 | 输出 runbook 与客观回传要求 |

## 5. 执行报告

执行报告至少包含：

```markdown
## 执行矩阵
| case_id | 测试面 | execution_ref | 执行状态 | 保真度(真连/模拟/手工) | 证据 |

## 编号覆盖
- 检查器命令与结果 / 人工对账表：
- 有编号无落点的 AC 清单（应为空）：

## 数据策略
- 前置方式：
- 清理方式：
- DB 校验：

## 失败分类
| case_id | 分类 | 证据 | 下一步 |

## 交付判断
- 可交付 / 不可交付：
- 真连绿 / 模拟绿分计（模拟绿逐条列真实链路收口去向）：
- 阻断项：
- 手工例外：
```

## 6. 与其他 skill 的边界

- 规范矩阵不足：回到 `test-standards`。
- 用例质量不足：回到 `test-case-design`。
- 项目命令和工具细节：进入项目执行 skill。
- 测试暴露产品缺陷：进入项目排障/RCA skill 或主线程修复流程。
