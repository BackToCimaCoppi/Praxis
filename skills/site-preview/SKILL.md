# 手机审阅站

本地原件是内容真值；审阅站是可更新的临时展示副本，不取得设计或业务裁决权。

## 准备材料

1. 确定输入材料及本地原件。HTML 保留视觉与必要依赖；Markdown 完整转换成手机可读的 HTML，不摘要或改变结论。
2. 在隔离 staging 目录中只放 `index.html` 和实际需要的本地 CSS、JS、图片、字体。缺少依赖时停止；禁止复制整个项目、凭据、`.env`、Git 元数据、数据库、日志或会话文件。
3. 使用本 skill 的 `scripts/site_preview.py` 管理本地目录。`init` 建站，`upsert` 新增或更新，`list` 查询，`remove` 移除单项，`clear` 清空材料，`lock` 保护并发写入；具体参数由 `--help` 查询。路径、站名和项目标识由使用者或项目配置提供，不写死在 skill 中。
4. 目录按项目、任务、材料三级 slug 组织；同一材料更新复用原 slug，保持目录和已发布直链稳定。本地 HTTP 打开首页与材料页，在手机宽度下检查可读性和依赖。

## 可选发布

- 只有当前环境存在已配置的托管能力、目标站点与访问策略可核实，且本次发布已获授权，才将本地目录发布。优先沿用项目明确指定的私有托管流程；有 Sites 能力时可调用其正式 building/hosting skill。不得自动创建公开站、扩大访问者或把临时令牌当交付链接。
- 发布前持有 `lock`；确认远端当前版本，避免用旧目录覆盖他人材料。构建、保存和部署成功后核验首页、材料直链与访问范围，再释放锁。失败时保留最后成功版本并报告阻塞，不声称发布成功。
- 未配置托管、当前模式禁止联网/部署或用户要求仅本地时，交付本地预览与目录路径，并明确“未发布”；不得将缺少托管视为材料制作失败。
- `remove` 只移除指定材料；`clear` 仅在用户明确要求清空全部预览时执行。两者均不删除本地原件，不承诺清除托管平台历史版本。

## 交付

报告材料名称和本地位置；已发布时附材料直链、首页和访问范围。设计预览的截图自检仍由 `design-preview` 完成；审阅意见由调用方写回正式文档。
