# 与现有 skill 的边界对照

本 skill（legacy-archaeology）与库内 `code-to-guide`、`code-to-7layer` 在「从代码反推」上有机制重叠。
本表逐机制划清边界，避免重复造轮子，也帮使用者「四选一」时知道该用哪个。

---

## 一、一句话定位

| Skill | 一句话 | 产物给谁 | 时效 |
|---|---|---|---|
| **legacy-archaeology** | 反推「业务/库/接口」三层下钻知识库，给重构 AI 注入背景 | 主要给 AI（重构前） | 一次性快照 |
| code-to-guide | 反推 AI 友好的项目导览，帮快速摸清陌生库 | AI / 新人 | 随项目演进 |
| code-to-7layer | 反推七层文档骨架的总控，系统性补全文档体系 | AI + 人，长期维护 | 持续治理 |

---

## 二、逐机制区别

| 机制 | legacy-archaeology | code-to-guide / code-to-7layer |
|---|---|---|
| 覆盖层 | **只三层**：业务逻辑/数据库/接口 | 全链路（需求/代码/测试/运行资产…七层 或 导览全貌） |
| 核心承诺 | **可审计覆盖 + 残余风险登记**，明确不承诺零遗漏 | 帮理解 / 建治理体系，不主打「完整性证明」 |
| 完整性机制 | 双台账 + 外部真值源差集 + 残缺性审计 | 不强调差集兜底 |
| 失传分级 | 有「事实/推测/失传」+ 失传三件套门槛 | 有事实/推断分级（7layer），无「失传」终态门槛 |
| 平台层 | 有：服务调用图增量、悬空边、待接通清单 | 无（单项目视角为主） |
| 写作风格 | 索引重、表格化、叙事轻（纯给 AI 检索） | 兼顾人读 |
| 维护取向 | 一次性快照、不防过期 | 随项目持续更新 |

---

## 三、复用而非另造

本 skill 刻意**复用**已验证机制，不重写：
- **fan-out 编排**：照 code-to-7layer 的「主 agent 扫→切块→派子 agent」笔法。
- **证据分级**：沿用「事实/推测」思路，叠加「失传」终态。
- **长文档拆分**：直接用 `long-doc-governance` 的拆分 + 引用修复。
- **收尾评审**：用 `adversarial-review`（但职责限定为「残缺性审计」，见 SKILL.md §9）。

---

## 四、衔接规则（避免产出冲突）

- 本 skill 产的知识库是**重构背景索引**，**不进**七层文档体系的正式真值层。
- 若同一项目既要重构背景（本 skill）又要长期文档治理（7layer），**先用本 skill 做一次性考古快照**
  作输入，再由 7layer 决定哪些沉淀为正式真值——本 skill 不替 7layer 下「这是需求真值」的结论。
- 不要在同一目录里同时跑本 skill 和 7layer 产出，避免两套文档互相覆盖。
