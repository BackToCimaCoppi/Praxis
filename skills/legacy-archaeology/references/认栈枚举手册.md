# 认栈枚举手册

本手册回答一件事：**给定一个老项目，怎么把「所有表 / 接口 / RPC / MQ 收发 / 定时任务 / 外部调用」
机械地枚举出来**，喂给对象覆盖台账。技术栈不预设——先认栈，再套对应锚点；认不出的走通用兜底。

> 关键前提：**白盒枚举永远不完整**。本手册的锚点只覆盖「框架按常规写法注册的入口」，照不到
> 反射调用、运行时动态拼接、字符串拼出来的 topic 等。所以枚举完**必须**叠加 SKILL.md §5.3 的
> 外部真值源差集，把照不到的盲区显式登记。

---

## 一、怎么认栈

扫这些信号判定技术栈组合：

| 看哪里 | 信号 → 判断 |
|---|---|
| `pom.xml` / `build.gradle` 依赖 | `spring-boot-starter-web`→Spring MVC；`mybatis`→MyBatis；`spring-cloud-starter-openfeign`→Feign；`dubbo`→Dubbo；`rocketmq`/`kafka`→对应 MQ；`quartz`→Quartz |
| 启动类注解 | `@SpringBootApplication`/`@EnableFeignClients`/`@EnableScheduling`/`@EnableDubbo` |
| 配置文件 | `application.yml` 里的 datasource / mq / registry 配置 |
| 目录约定 | `mapper/`、`*Mapper.xml`、`controller/`、`consumer/`、`job/` |

认不出框架 → 走「六、通用兜底法」。

---

## 二、HTTP 接口

| 栈 | 枚举锚点 |
|---|---|
| Spring MVC / Boot | `@RequestMapping`/`@GetMapping`/`@PostMapping`/`@PutMapping`/`@DeleteMapping`（类级 + 方法级路径拼接） |
| JAX-RS | `@Path` + `@GET`/`@POST` |
| 老 Servlet | `web.xml` 的 `<servlet-mapping>` + `@WebServlet` |

> 盲区：网关层改写的路由、`@RequestMapping` 用常量/变量拼的路径。→ 用网关路由表差集补。

## 三、RPC（服务间调用）

| 栈 | 枚举锚点 |
|---|---|
| Feign（调出） | `@FeignClient` 接口 + 方法上的 `@RequestMapping` |
| Dubbo（暴露/引用） | `@DubboService`（暴露）/ `@DubboReference`（引用）；XML 的 `<dubbo:service>`/`<dubbo:reference>` |
| gRPC | `.proto` service 定义 + 生成的 stub |

> 盲区：泛化调用（Dubbo `GenericService`）、反射式 RPC。→ 注册中心服务列表差集补。

## 四、MQ 收发

| 栈 | 枚举锚点 |
|---|---|
| RocketMQ | `@RocketMQMessageListener`（消费）；`rocketMQTemplate.send*`（发送）的 topic 参数 |
| Kafka | `@KafkaListener`（消费）；`kafkaTemplate.send`（发送） |
| RabbitMQ | `@RabbitListener`；`rabbitTemplate.convertAndSend` |

> 盲区：topic 用变量/配置/字符串拼接的发送点。→ broker topic 列表差集补；grep `send` 类调用兜底。

## 五、定时任务

| 栈 | 枚举锚点 |
|---|---|
| Spring | `@Scheduled`（cron/fixedRate） |
| Quartz | `JobDetail` 注册、`*Job implements Job` |
| XXL-JOB / 弹性调度 | 注解 `@XxlJob` + 调度中心配置（代码里只有 handler，调度配置在平台） |

> 盲区：调度配置在外部平台（XXL-JOB 控制台、crontab）。→ 调度平台导出差集补。

## 六、表 / 数据库

| 栈 | 枚举锚点 |
|---|---|
| MyBatis | `*Mapper.xml` 的 `<table>`/SQL 里的表名；`@Select`/`@Insert` 注解 SQL |
| JPA / Hibernate | `@Entity` + `@Table` |
| JdbcTemplate / 原生 | grep SQL 字符串里的 `from`/`into`/`update` 表名 |

> 盲区：运行时动态拼接的 SQL、分库分表的物理表。→ DB `information_schema.tables` 差集补（最权威）。

## 七、外部调用（第三方 / HTTP 出站）

锚点：`RestTemplate`/`WebClient`/`OkHttp`/`HttpClient` 的调用点、SDK 客户端初始化。
> 盲区多，靠 grep + 配置里的外部地址兜底。

---

## 八、通用兜底法（认不出栈 / 框架照不到时）

不依赖框架识别，按「行为」捞：
1. **grep 入口特征**：`controller`/`service`/`listener`/`job`/`mapper`/`client` 等命名约定 + URL 字符串
   + SQL 字符串 + `send`/`publish`/`invoke` 调用。
2. **配置文件兜底**：所有 `*.yml`/`*.properties`/`*.xml` 里的 url / topic / cron / datasource。
3. **外部真值源永远优先**：网关路由表、注册中心、`information_schema`、broker topic、调度平台导出
   ——这些是运行时真值，比任何白盒扫描都全。拿到就做差集，是兜底的兜底。
   > ⚠ 差集前**必须按服务边界裁剪**这些真值源（它们多是全平台共享的，直接差集会把别服务的对象误报成
   > 本项目盲区）——裁剪规则见 SKILL.md §5.3 第一步。

---

## 九、项目补丁扩展区

公司特有的框架 / 自研中间件的枚举锚点，由项目补丁在此追加（不改本手册通用部分）：

```
〔填空：公司自研 RPC 框架 X 的枚举锚点〕     # 示例：注解 @XService 标注的接口即暴露点
〔填空：自研调度框架 Y 的枚举锚点〕
〔填空：特有的表路由 / 分库分表中间件〕
```
