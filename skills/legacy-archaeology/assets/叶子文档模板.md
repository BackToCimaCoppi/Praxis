# 叶子文档模板（business-logic.md / database.md / api.md）

> 一个模块目录下的三个 L3 叶子，固定 ASCII 文件名。下面是三份各自的骨架，外加一个 L2 模块 README 迷你骨架。
> 通用规则：每条都挂证据标注 ——【事实｜文件:行】/【推测｜依据】/【待人工｜原因】；拿不准的进「候选区」。
> **子 agent 不得产出【失传】**（它给不了人工背书）——最多标【待人工｜疑似失传】；
> 【失传】是终态，只能由主 agent 走完三件套（穷尽白盒 + 已问用户 + 用户确认不可考）+ 人工背书后回填。
> 示例一律用虚构域（订单/商品/支付），不带任何真实业务名。

---

## A. business-logic.md（业务逻辑）

```markdown
# 〔模块名〕· 业务逻辑

## 规则：〔规则名，示例：订单超时自动关闭〕
- 触发：〔示例：定时任务每 5 分钟扫一次〕         【事实｜OrderJob:30】
- 条件：〔示例：状态=待支付 且 创建超 30 分钟〕    【事实｜OrderService:88】
- 动作：〔示例：置已关闭、回滚库存〕              【事实｜OrderService:95】
- ⚠ 〔示例：30 分钟是否可配？未见配置项〕         【推测｜疑似硬编码】
- ⚠ 〔示例：关闭后是否发通知？相关代码找不到〕    【待人工｜疑似失传，需主 agent 走三件套确认】

## 规则：〔下一条…〕

## 候选区（拿不准是不是业务规则，先保全，待主 agent 归并）
- 〔示例：下单时对金额做了 ×100 处理，疑似分/元换算，也可能是某次临时改动〕【候选｜OrderService:40】
```

> 按业务决策类型一条不漏：状态机 / 分支条件 / 计算规则(含运算顺序) / 校验 / 副作用触发 /
> 边界异常的业务处理 / 隐藏规则 / 权限策略 / 租户隔离 / 数据生命周期 / 补偿流程 / 批处理重跑 /
> 灰度开关 / 配置驱动规则。

## B. database.md（数据库）

```markdown
# 〔模块名〕· 数据库

## 表：〔t_order〕  〔一句话业务含义〕
| 字段 | 类型 | 业务含义 | 约束（业务语义相关的保留） |
|---|---|---|---|
| id | bigint | 主键 | PK |
| status | tinyint | 订单状态 | 〔状态码字典见下〕 |
| amount | decimal(10,2) | 金额 | 精度 2 位=分级保留【精度是业务规则】 |
| out_no | varchar | 外部单号 | UNIQUE【唯一去重规则】 |

- 状态码字典：0=待支付 / 1=已支付 / 2=已关闭 …            【事实｜OrderStatusEnum:5】
- 隐式外键（应用层 join，无 DB 约束）：`t_order.user_id → t_user.id` 【推测｜OrderMapper.xml:60】
- 关键索引：`idx_status_create_time`（揭示「按状态+时间扫单」的访问模式）

## 整层置信度声明
〔示例：本层基于 information_schema 校验，高置信〕/
〔示例：未拿到 schema，整层为代码推断、低置信〕
```

> 丢纯物理 DDL（引擎/字符集）；保留 非空/唯一/默认值/级联/精度长度 等承载业务语义的约束。

## C. api.md（接口）

```markdown
# 〔模块名〕· 接口

## 〔POST /order/create〕  〔一句话用途〕
- 入参：〔关键字段 + 业务约束，示例：amount>0、items 非空〕     【事实｜OrderController:42】
- 出参：〔关键字段 + 状态码语义，示例：code=0 成功 / 4001 库存不足〕
- 幂等：〔示例：靠 out_no 唯一约束保证〕                       【事实｜…】
- 鉴权：〔示例：需登录态 token〕
- 运行语义：〔重试/超时退化/错误码映射/调用顺序，示例：超时后不自动重试，前端需查单兜底〕
- 兼容性：〔示例：保留已废弃字段 coupon_id 兼容旧客户端〕      【推测｜OrderController:50】
- 调用方：
  - 本服务内：〔静态可确定，示例：OrderJob 重试调用〕
  - 跨服务：〔借平台调用图反查，不全标未知，示例：网关 + ？（可能有别服务，待平台层收敛）〕
```

> 重点是契约 + 运行语义（失败后业务怎么走），不是 controller 代码。
> 「谁在调它」跨服务部分务必标「未知/待补」，绝不伪装成完整列表。

## D. README.md（L2 模块导航节点，迷你骨架）

> §2.2 硬规则：每个目录必有 README 当导航节点。模块层的 README 极简，只做下钻路标。

```markdown
# 〔模块名〕

〔一句话：本模块负责什么，示例：订单创建与超时关闭〕

- [业务逻辑](business-logic.md)
- [数据库](database.md)
- [接口](api.md)

〔如有子模块，逐个列下钻链接；没有就删掉这行〕
- [子模块 X](子模块X/README.md)
```
