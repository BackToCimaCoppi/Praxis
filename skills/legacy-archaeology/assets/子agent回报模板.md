# 子 agent 回报模板

> 每个子 agent 调查完一个模块后，**把回报落盘成这个结构化格式**（不是写一段自然语言）。
> 主 agent 只读这份摘要 + 据此决定二轮补派，所以字段必须齐、可机械消费——这是「状态不放记忆」的落点。
> 复制后逐项填。

---

## 本轮回报 · 〔服务标识〕/〔模块名〕 · 第 〔n〕 轮

### 1. 本轮产出文件
- 〔示例：下单/business-logic.md（新建）〕
- 〔示例：下单/database.md（新建，整层低置信，未拿 schema）〕
- 〔示例：下单/api.md（新建）〕

### 2. 台账变更（回填了哪些行）
| 对象标识 | 旧状态 | 新状态 |
|---|---|---|
| 〔t_order〕 | 待调查 | 已记录 |
| 〔order_paid 消费〕 | 待调查 | 推测 |
| 〔closeExpiredOrder〕 | 待调查 | 待人工 |

### 3. 未决-阻塞清单（高优，主 agent 必须收口）
> 不查清这点整篇就建立在错误前提上的点。每条写：阻塞在哪、缺什么、需要谁补。
- 〔示例：t_order.status 的 3 与 4 两个码含义不明，直接决定退款分支怎么写；需用户确认或查状态枚举来源〕
- 〔无则写「无」〕

### 4. 待确认清单（非阻塞，攒批问用户）
- 〔示例：超时 30 分钟是否可配？未见配置项，标了【推测】，可继续〕
- 〔无则写「无」〕

### 5. 建议补派范围
> 若本模块还需深挖，建议下一轮派什么。
- 〔示例：拿到 status 码含义后，补派一轮专写退款状态机〕
- 〔示例：本模块已收敛，无需补派〕

### 6. 轮次计数
- 本模块已用 〔n〕 / N 轮（N 默认 3，含阻塞收口轮）。
- 〔示例：还剩 1 轮；若下一轮仍有阻塞则封板转「待人工」〕
