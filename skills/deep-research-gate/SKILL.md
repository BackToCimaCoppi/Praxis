# 扇出与深度研究安全门

## 分类

判据三问：任务数量是否无法预先计数？子任务是否可以再派生？是否让调查者自行决定调查范围和深度？任一回答“是”，按无界调查处理。已枚举、可计算上界、无递归的叶子任务直接并行。

## 无界调查开闸

1. 写清目标、预计调用与成本、最大并发、最大层数、时间或 token 上限、停止条件和交付物，取得用户同意。
2. 检查当前运行时有无递归派生、深度研究或自动工作流功能；可用时关闭自动触发。无法关闭的，缩减为有界任务或明确人工监督，不让叶子代理持有派生权限。
3. 只启动获批范围，记录实际扩张。达到预算、深度或时间上限立即收口，未完成部分单独报告。
4. 结束时恢复临时改变的运行时配置，并在报告结果前核查恢复状态。

## 硬规则

- 子任务默认是叶子。授予只读、范围限定的工具，不给派生代理、工作流、外部发布或不必要的写权限。
- 有界并行不可因为无界调查风险而擅自串行化；但不得突破当前运行时的并发上限。
- 运行时若无法提供预期隔离，不声称已建立引擎级保护。改用可验证的任务范围、预算与监督。
- 用户授权的一次无界调查不自动延续到另一轮或另一主题。
