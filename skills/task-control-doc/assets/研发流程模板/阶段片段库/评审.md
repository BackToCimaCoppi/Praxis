# 阶段片段：评审（实例化为 `T{n}-评审-{被评对象}.md`）

> 本文件是「评审」阶段的**独立片段模板**。实例化时替换 `{{槽位}}`、定编号、删本说明行。
> **仅风险触发时使用**：命中死亡线区域 / 跨域（≥2 域）/ 破坏接口或数据契约。否则评审塌缩进对应设计/蓝图/测试子任务末步，不单列。

## 当前状态

- **状态**：待完成
- **依赖**：T<被评审的产出子任务>
- **阻塞**：T<下游>

## 子任务背景

评审阶段（独立）：对上游产出（轻量设计 / 施工蓝图 / 测试用例）做对抗评审。因本任务命中高风险（死亡线/跨域/契约破坏），评审单列成子任务，确保被独立、严肃地审。

## 强制阅读（精准 1-3 个）

- `{{评审 skill}}`：对抗评审 skill —— 读完获得评审发起与裁决流程
- 上游被评审产物：`_shared/T<上游>-{轻量设计方案/施工蓝图/测试用例}.md`

## 输入

- 被评审产物全文

## 要做的事情（固定四步）

1. 跑 `{{评审 skill}}` 对抗评审，产出裁决报告
2. 把 AI 拿不准的逐条整理为「用户决策点」
3. 用户裁决
4. 把采纳结论**回补**到被评审产物（设计方案 / 蓝图 / 测试用例）

## 不做什么

- 不改被评审产物之外的任何东西（回补只动被评对象）
- 不替用户拍板死亡线项——必须升级
- 不顺手做下游子任务

## 预期效果

被评审产物经独立对抗评审 + 用户裁决并回补，可放心进入下游。

## 输出物

- `_shared/T{n}-对抗评审报告.md`（蓝图评审用 `_shared/T{n}-蓝图评审报告.md`，§1.1.1 标准名）
- 回补后的被评审产物（原文件更新）

## 完成判定

- [ ] 对抗评审报告已产出（逐条裁决 + 来源标注）
- [ ] 用户决策点已逐条裁决
- [ ] 采纳结论已回补被评审产物
- [ ] 父级 `README.md` 子任务总表本行状态改为 `已完成`
- [ ] 父级 `README.md` 进展记录已追加一行

## 风险与注意事项

- 评审子任务边界 = 评审 + 决策 + 回补；**不**改下游、不替用户拍板
- 死亡线项必须升级用户，不得 AI 自决
