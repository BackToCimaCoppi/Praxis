## 子任务背景

评审阶段（独立）：对上游产出（轻量设计 / 测试用例 / goal 章程）做对抗评审。**默认这三次评审都塌缩进对应子任务末步**；因本任务命中高风险（死亡线/跨域/契约破坏），才单列成子任务。

**三次评审各有专属口径卡**（由 `{{评审 skill}}` 提供），口径不同、火力不同——**不要用同一套问法审三种东西**：

| 评审对象 | 口径卡评什么 | 硬约束 |
|---|---|---|
| 轻量设计 | 重大设计问题（改变业务结果 / 不可逆架构归属） | 小问题由当前主线程裁决并直接改，一次改好，不留下游闸门 |
| 测试用例 | **评测试强度与可追溯完整性** | 每个 AC 必须同时追到 SD 与正式规格；发现“设计没说”必须回填设计并在规格冻结阶段物化 |
| goal 章程 | **红队攻击**：扮演一个想交差的执行者，它会怎么钻空子？ | 四问 A 作弊 / **B 必卡** / C 漏停 / D 断点丢失，每类最多 2 条，必须给具体攻击场景 |

## 强制阅读（核心必读 1-3 个，准入下限、非视野上限）

- 上游被评审产物：`_shared/T<上游>-{轻量设计方案/测试用例/goal章程}.md`

## 输入

- 被评审产物全文

## 要做的事情（固定五步）

1. 对同一对象/基线只跑一次 `{{评审 skill}}` 开放式对抗评审，产出带 `AR-x` 的裁决报告
2. 把全部真实业务决策缺口合并成一张表，一次性交给用户
3. 用户裁决后逐项写入 `_shared/用户裁决记录.md#DEC-x`；禁止用 AI 摘要或评审建议写“用户已批准”
4. 按处置权矩阵落地：桶1 回补被评对象；桶2 追加 `_shared/自愈清单.md`
5. 调 `{{封闭验收 skill}}`：本工具一个原生子线程只读检查固定整改清单，主线程逐条裁决；结果追加原评审报告，`PASS` 后关闭，禁止 R2/R3

## 不做什么

- 不改被评审产物之外的任何东西（回补只动被评对象；**桶2 条目落 `_shared/自愈清单.md` 是唯一例外**）
- 不替用户拍板死亡线项——必须升级
- 不顺手做下游子任务

## 预期效果

被评审产物经一次独立对抗评审、当前主线程逐条裁决、必要的用户业务裁决与回补后，可放心进入下游。
