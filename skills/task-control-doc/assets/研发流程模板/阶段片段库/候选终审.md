# 阶段片段：候选终审（实例化为 `T{n}-候选终审.md`）

> 本文件是「候选终审」阶段的**片段模板**。实例化时替换 `{{槽位}}`、定编号、删本说明行。
> **本阶段不可塌缩、不可省略且只读**——goal 交付 `CANDIDATE_READY` 后无人终审是结构缺口；终审发现问题后自行整改则会把终审变成第二个施工 loop。

## 当前状态

- **状态**：待完成
- **依赖**：T<goal 执行>
- **阻塞**：无

## 子任务背景

goal 已按章程自主跑完并交付精确候选（commit/tree SHA + 执行证据清单 + 飞行日志），状态 `CANDIDATE_READY`。本阶段是**流程终点的唯一独立验收**：对照冻结正式真值检查候选的实现、真实断言与执行证据——闸门全绿只证明报告结构与追溯完整，**语义正确性由本阶段兜底**。

本阶段默认由**全新上下文**执行，避免生产候选的同一上下文自证；它只读检查，不实施整改。

## 强制阅读（核心必读 1-3 个，准入下限、非视野上限）

- `_shared/T<goal 执行>-交付记录.md` + 执行证据清单 + `{{候选终审 skill}}`：候选 SHA、测试矩阵结果、豁免明细；后者必须展开到测试执行证据协议 + 项目证据规则，用于重算语义证据分布、消费者完整性与原生断言事件
- `_shared/T<goal 章程>-goal章程.md`：目标、已知豁免与交接面定义
- `_shared/T<规格冻结>-规格物化覆盖报告.md`：冻结锚点（`design_index_hash` / `spec_hash`）

## 输入

- 精确候选（commit/tree SHA）+ 执行证据清单 + 飞行日志
- 冻结的正式 L1–L7 与用例规格

## 写入范围（机器检查）

- `start_commit`: `<终审开工前当前提交 SHA>`
- `allowed_write_paths`: `本工作包`、`_shared/T{n}-候选终审报告.md`
- `allowed_cross_task_writes`: `README.md::子任务总表`、`README.md::进展记录`、被退回工作包 `::当前状态`
- 交付前对终审候选提交运行 `check_write_scope.py`；任何产品/规格/测试/证据文件出现于 diff 均失败

## 要做的事情

1. 锁定候选 commit/tree SHA，确认工作树干净，复验规格清单与执行证据清单哈希
2. **打开真实测试落点**核对——不是只看 `AC-x` 字面出现：断言语义、强制测试形状（真并发/时钟边界/双路径/批量隔离）是否与冻结规格一致
3. 核对执行状态封闭集：只有 `VERIFIED` 计入通过；`BLOCKED / MISSING` 逐条核明细，`WAIVED` 逐条核正式来源或 `DEC-x`
4. 100% 运行语义证据检查器；全量打开死亡线/安全/并发/真实环境/手工/多面 AC、所有重复簇与等价组，再按候选哈希确定性抽取 30 条普通 AC，覆盖全部实际执行面
5. 逐条审阅飞行日志的红→绿翻转与自愈记录，确认无语义改写混入
6. 核对**真实链路闭合度**：逐条过 `env_fidelity=simulated` 与 `BLOCKED` 清单，确认交付记录用人话写明真实链路断在哪、由谁何时接通
7. 高风险/死亡线候选：仅在用户或项目规则要求时走 `{{评审 skill}}` 代码候选口径（同对象哈希、同真值基线只开放一次）；普通候选由全新上下文按本清单执行
8. 意见逐条裁决并按唯一路由退回：产品、测试资产/runner/夹具/环境适配/证据工具 → **同一 goal 执行**；冻结用例语义 / 正式规格 / 业务语义 → **默认热修**（终审报告附修改方案：决策项 + 上游修改清单 + 失效证据清单 + 恢复点；业务决策负责人按项目治理批准后改齐并回同一 goal 补受影响切片，不打回上游子任务；热修不可靠且获相应批准才回退用例设计或轻量设计 + 规格冻结）；外部授权 → 对应环境所有者或发布授权人补权
9. 按影响面失效：goal 内可逆修复只重跑受影响验证和证据；用例变化使对应 AC 与下游失效；正式规格变化才重建章程及全部下游。禁止 runner 小错引发全链回炉

## 不做什么

- 不重做施工、不修任何缺陷、不扩张验收范围、不新增评审轮次
- 不修改产品、正式规格、测试资产/runner、冻结件或执行证据；只写终审报告、README 状态/进展与受控退回指针
- 不把 `BLOCKED/MISSING` 折算进通过率；不接受无来源 `WAIVED`
- 不发明规则、不新增硬门

## 预期效果

候选获得**最终验收封印**（或带证据退回）；用户拿到一份可直接拍板的终审报告。

## 输出物

- `_shared/T{n}-候选终审报告.md`（§1.1.1 标准名）：候选 SHA / 逐项核对结果 / 固定问题清单 / 唯一退回指针或最终封印

## 完成判定

- [ ] 候选 SHA 锁定、工作树干净、哈希复验一致
- [ ] 全部 `AC-x` 真实落点核对完成；`VERIFIED` 之外的状态逐条有明细与来源
- [ ] 语义证据机器重算通过；代理观测、非法重复消费、孤儿套件、未消费失败/跳过、未执行绑定与多部件缺口均为零；强制全量项与确定性 30 条抽检完成
- [ ] 发现的意见全部裁决并给唯一责任路由；终审未实施任何整改
- [ ] 最终验收封印已出具（存在 `BLOCKED/MISSING`、无来源 `WAIVED` 或未闭环发现时**禁止**出具）
- [ ] **此时才**把 T<goal 执行> 与本行状态改为 `已完成`；父级 `README.md` 进展记录已追加一行
