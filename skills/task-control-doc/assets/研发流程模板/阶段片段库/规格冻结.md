## 子任务背景

本阶段把任务最终真值切片内的**新设计 + 既有腐败**一起收敛进正式文档并冻结，作为 goal 执行的前置依赖与法律。目标不是“写过文档”，而是证明轻量设计与测试用例没有一条规范性语义丢失。

判据（`{{规格冻结 skill}}` / 七层体系 §5.0）：

> **把代码全删了，能照文档重做出来吗？** 能 → 那它就是规格，属本阶段。

因此本阶段冻的不只是契约：**需求 / 交互 / 接口契约 / 表结构 / 架构骨架与核心业务链路 / 用例规格，全部**。而实现细节（函数内部、样式写法、DTO 转换、SQL、标准 CRUD）属**代码自由范围，不进任何文档**——删了也能照规格重做，写进来只会让文档追代码、开始腐烂。

## 要做的事情

1. **物化遍**：逐条读取全部 `SD-x` 与 `AC-x`，把规范性语义写入职责正确的正式 L1–L7；发现设计空洞先回补设计索引再物化，禁止摘要式回写
2. **切片覆盖遍**：按能力/状态/接口/数据/架构/前端/测试链路检查最终真值切片；L1–L7 每层标记「已修订 / 已核验无需改 / 不适用（证据）」
3. **跨层可满足性遍**：逐条证明 L5/L6/L7 要求的状态、快照、预留、时点口径在 L3/L4/域内有合法输入与承载，或正式证明无需持久化；不得把新接口/Schema 留给 Goal 发明
4. **业务语义差异遍**：对比评审前设计基线、`DEC-x` 与最终正式规格，清零无来源的新增/删除/改写；评审建议不得升格为业务规则
5. 一并改正最终真值切片内的全部已知历史割裂；切片外债务只登记，不扩张本任务
6. 产出 `_shared/T{n}-规格物化覆盖报告.md` 与同名 `.json`：逐条证明 `SD-x → 正式规格锚点 → AC-x`，记录五项 pass 与 `known_in_scope_debt: []`；无语义差异或无开放评审时也必须给可复核理由，不能用空数组静默跳过
7. 运行规格物化检查器，五项全绿后统一记录正式文档版本、用例 `spec_hash`、`frozen_at/frozen_by`

## 不做什么

- **不写实现细节**（函数内部 / CSS / DTO 转换 / SQL / 标准 CRUD）——那是代码自由范围，写进来就把设计型层变成了代码镜像层
- 不碰代码
- 不做最终真值切片之外的无边界大修；但调查清单漏掉而切片实际涉及的腐败必须修，不能以“不在初始清单”为由绕过
