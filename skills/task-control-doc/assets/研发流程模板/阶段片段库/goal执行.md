# 阶段片段：goal 执行（实例化为 `T{n}-goal执行.md`）

> 本文件是「goal 执行」阶段的**片段模板**。实例化时替换 `{{槽位}}`、定编号、删本说明行。

> **本片段是工作包壳**：真正统治执行的是 `_shared/T<goal 章程>-goal章程.md`，工作包与章程冲突时**以章程为准**。

## 子任务背景

goal 执行阶段：按已拍板的章程**自主跑到底**——M0 检查并修复执行面 → 产品施工 → 提交 → 交付/发布 → 跑冻结测试矩阵 → 封存执行证据，全在一个 loop 内；只有计划内人工里程碑或章程出口才交还控制权。

**这是流水线上唯一"结果管控"的阶段**：人不在工序里，人在终点。质量由**可判定的验证器**（冻结用例 `spec_hash` + 检查器 + 部署健康检查）保证，不由人逐步审查保证。

## 要做的事情

> 内部工序编排固定（详见 `{{goal 章程 skill}}`），**每步审核都是 AI 自审或机器检查器，零人工闸门**：

```
M0：各命中面最小健康探针并自愈 → 产品代码 → [检查器：机器判定]
→ 提交 → 交付/发布 → 跑冻结测试矩阵 → raw+采集时信封 → AC 映射与账本 → 每切片收尾执行记录
```

1. 用「会话启动提示词」段回填的 `/goal` 条件**开启 goal 模式**（无人值守需同时开 auto mode），按章程里程碑逐片推进；每片跑通它的**验证命令**再进下一片，**且把命令真实输出贴进对话**——evaluator 不跑命令、不读文件，对话是它唯一判据（`{{goal 章程 skill}}` §13.2）
2. 开工先读启动服务单并执行 M0：服务单中会话、路径、命令或工具过期时直接刷新；每个命中测试面运行一个最小健康探针，执行基础设施问题在 goal 内直接修复；输出 `_shared/T{n}-goal启动检查.md`，不得给逐 AC 签发 Ready 状态
3. 代码合规跑 `{{goal 执行绑定}}` 的**检查器命令**，不靠自觉
4. 按章程授权**提交**（建总控即预授权；**推送需章程显式授权**）
5. 交付 / 发布 + 跑冻结测试矩阵；执行证据按 raw → 采集时不可变信封 → AC 映射 → 状态账本单向生成，候选交付前运行执行证据检查器
6. **自愈 + 记飞行日志**：产品或执行基础设施缺陷都在同一 goal 内修；每条记录时间 / 类别 / 改了什么 / 依据哪份冻结真值 / 影响哪些测试与证据，并重跑影响面
7. 文档处置三分：纯实现自由不进七层；影响可重建且现有真值给出唯一方向的意外缺口走有界重新冻结；新业务语义走回炉。禁止只补 L5/L6，施工前已知腐败不得在 goal 中计划性偿债

## 不做什么

- **不在施工路径直接改冻结用例规格**（`spec_hash` 是完成判定的锚）；只有有界重新冻结可同步改 `SD→SPEC→AC` 并生成新哈希，且不得削弱既有断言。**不把失败测试改成弱断言 / 跳过 / mock 冒充真实环境**
- 不削弱测试资产；允许修测试脚本、runner、夹具、环境适配器和证据工具，但修复必须更接近冻结规格，并按影响面重跑，不得把可逆缺陷退回上游
- 不在 goal 内走对抗评审（它引入 loop 外观点，场景不同、上下文不同，产出的是噪音）
- **不发明规则**、不给自己加硬门、不新增死亡线
- **不为补背景派子 agent**；有界并行仅限章程已枚举的切片，叶子级，禁二级派生

> **注意：这里没有"发现 bug 不许就地改"这条**。根因已证实、修复路径唯一、可回滚、且不改变业务规则/对外契约/数据语义的缺陷 → **直接修 + 补自动回归 + 记日志**。把"发现真实代码缺陷"泛化成停机理由，正是旧流程卡死的主因之一。

## 风险与注意事项

- **停机只剩章程 §4 白名单三条**：冻结真值矛盾 / 死亡线业务变更 / 未预授权不可逆或外发动作。凭据定位、实现取舍与重复失败都不取得用户裁决权
- 安全路径穷尽或达到限轮时只交付 `EXECUTION_BLOCKED` 断点，恢复后回同一 goal 受影响切片，不自动前拉
- **第三个出口是回炉**：证明上游规格真错了 → 带证据终止，回设计步重来。别在"硬改代码绕过"和"停机问人"之间二选一
- **测试套件是隐蔽的能力通道**：跑测试 = 执行任意代码 = 可达任何网络端点。章程禁止段的可达性边界对测试同样生效
- **红→绿翻转必须记日志**：测试变绿是因为改了代码（正常）还是改了脚本（须逐条留痕）？判据是**改完更接近规格还是更接近代码**——更接近规格 = 忠实化，更接近代码 = 作弊
