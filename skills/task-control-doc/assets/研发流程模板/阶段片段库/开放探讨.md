# 阶段片段：开放探讨（实例化为 `T{n}-探讨-{细分}.md`）

> 本文件是「开放探讨」阶段的**片段模板**。实例化时替换 `{{槽位}}`、定编号、删本说明行。
> 可拆两份：「产品需求探讨」（业务形态/流程）+「核心技术探讨」（选型/接口/数据/脚手架/复用），各占一个编号、可并行。

## 当前状态

- **状态**：待完成
- **依赖**：T<调查>
- **阻塞**：T<设计>

## 子任务背景

开放探讨阶段：在多轮人机对话中敲定**还没定的东西**——产品线敲定业务形态与流程；技术线敲定技术选型、代码业务流程、关键接口、DB 设计、关键脚手架与代码复用。结论沉成探讨纪要，喂给设计阶段。

## 强制阅读（核心必读 1-3 个，准入下限、非视野上限）

- 上游 `_shared/T<调查>-调查报告.md`：已知真值与割裂点
- `{{探讨依据}}`：需求/契约层文档 —— 读完获得既有需求与接口约束

## 背景导航（可选，不设上限）

- `路径`：读它获得什么背景（读不读由执行会话自行判断；亲自读，不派 agent）

## 输入

- 调查报告（含割裂点清单）
- 用户在探讨中逐点拍板的意见

## 要做的事情

1. 列出本任务"待定决策点"清单（产品线 / 技术线）
2. 多轮探讨，每个决策点锁死唯一选择（选了什么 / 放弃什么 / 为什么）
3. 沉成探讨纪要（按决策点组织，含未决项标注）

## 不做什么

- 不写轻量设计方案（那是下一阶段；本阶段只敲决策，不成体系文档）
- 不出设计方案、不碰代码（探讨定的是方向，设计定的是决策）
- 不替业务决策负责人拍板重大取舍——拿不准的列出来交对应角色裁决

## 预期效果

本任务"该怎么做"的核心决策点全部锁死，设计阶段可直接据此成文。

## 输出物

- `_shared/T{n}-探讨纪要.md`：决策点 → 锁定结论（含理由），未决项单列

## 完成判定

- [ ] 探讨纪要已产出，关键决策点均锁定唯一选择
- [ ] 未决项已显式标注（交设计/评审或用户）
- [ ] 父级 `README.md` 子任务总表本行状态改为 `已完成`
- [ ] 父级 `README.md` 进展记录已追加一行

## 风险与注意事项

- 精炼 ≠ 含糊：每个决策点必须锁死唯一选择，不能停留在"可以考虑 A 或 B"
- 探讨纪要不是聊天记录转录，只留高价值结论
