> **红队评审默认塌缩进本片段末步，且每次必做**（不可跳过）；命中死亡线/跨域/契约破坏才拆独立「评审」子任务。

## 子任务背景

goal 章程阶段：把接下来几小时的自主施工压成一份**执行契约**——目标（可判定终态）+ 里程碑（施工切片）+ 权限边界 + 停机白名单 + 回炉出口 + 已知豁免 + 文档动作清单 + 飞行日志与验收面。

**这是全流程唯一没有下游兜底的产物**：设计错了有测试兜底，**章程错了没有任何东西兜底**——它统治后续全部自主执行。所以红队评审在这里每次必做。

- `{{goal 执行绑定}}`：交付/部署 skill、测试执行路由、项目执行 skill、检查器命令 —— 写目标与验证器时要引用

## 要做的事情

1. 先验证规格物化覆盖报告；缺失、五项 pass 任一不真、哈希不一致或任务切片内仍有已知文档债务 → **不得写章程，退回 T<规格冻结>**
2. 按 `{{goal 章程 skill}}` 写章程，落 `_shared/T{n}-goal章程.md`（**≤100 行，硬上限**）
3. **切片**：按最终真值切片 + 用例矩阵切里程碑，要素表一行一片。判失败：**任一切片不能独立编译或独立验证 → 重新切**
4. **收自愈清单**：只收施工时才能决定的事项；已知规格腐败不得包装成自愈项
5. **扫测试套件里硬编码的外部端点**，据结果写「禁止段」
6. **（评审塌缩，每次必做）** 同一章程对象/基线只跑一次 `{{评审 skill}}` 红队四问；按裁决整改后调 `{{封闭验收 skill}}`，本工具原生子线程检查原 A/B/C/D 项、主线程逐条裁决，`PASS` 后关闭，禁止 R2/R3
7. 章程交用户拍板
8. **（拍板之后，本阶段最后一步）生成 goal 启动物**，按 `{{goal 章程 skill}}` §13.3～§13.5 产出**一条 `/goal` 完成条件**（四段：开工指令 / 完成条件 + 举证义务 / 关键约束 / 四类出口；典型 600–1200 字符，上限 4000）。**不要再另写一份「会话启动提示词」**——条件既是 evaluator 的判据又是首轮指令，拆两块 = 双份真值 = 必漂移；总控三要素承载在条件内。逐段取料照 §13.4 的表，别自由发挥。写完**回写进 `T<goal 执行>-goal执行.md` 的「会话启动提示词」段**（标题保持原名、其后紧跟代码块，否则总控脚本抓不到）——这是本阶段唯一被授权的跨子任务写入，**只准写这一段**
   > **必须拍板后做**：原料全部来自终版章程，章程还在改就写它 = 猜。红队整改会改动 §1/§3.2，提前写必漂移

## 不做什么

- 不写代码、不写测试脚本（属 T<goal 执行>）
- 除下游 `T<goal 执行>-goal执行.md` 的「**会话启动提示词**」一段外，**不写入任何其他子任务的文件**——那一段是本阶段唯一被授权的跨子任务写入（见「要做的事情」第 8 步），其余照总控单子任务边界执行
- **不在章程里发明规则**：「硬门」「死亡线」「必须审批」一律只是执行建议，不具停机权；**死亡线是封闭清单，无权新增**
- **不给下游新增闸门**（反棘轮）
- **不放宽 ≤100 行上限**：写不下是切片切大了或话说啰嗦了。实测放不下 → 报实际行数给用户裁决，不自行调整

## 风险与注意事项

- **B（必卡路径）是四问里最重要的一问**：A/C/D 找的是"边界太松"，**B 找的是"边界太紧"**。历史上所有卡死痛苦都来自 B，而所有评审都只在找 A/C/D
- 「必须做但章程没授权」**不是停机理由，是章程写漏了**——正是 B 该抓的
- 切片不能独立验证 = goal 断点续跑时**根本没有断点**
