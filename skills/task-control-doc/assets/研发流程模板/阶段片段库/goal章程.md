# 阶段片段：goal 章程（实例化为 `T{n}-goal章程.md`）

> 本文件是「goal 章程」阶段的**片段模板**。实例化时替换 `{{槽位}}`、定编号、删本说明行。
> **本片段是工作包壳，不复述方法论**——章程怎么写（8 节模板 / ≤100 行上限 / 目标的正确形式 / 可达性边界 / 防作弊三层防线 / 已知坑）全在 `{{goal 章程 skill}}` 里，唯一真值源，此处不重复。
> **红队评审按风险触发**：命中死亡线/跨域/契约破坏，或用户显式要求时才执行；整改后走封闭验收。

## 子任务背景

goal 章程阶段：在规格冻结和授权明确的前提下，把接下来几小时的自主执行压成一份**执行契约**，并产出一份无闸门的 goal 启动服务单，提前清算可预见的候选无关用户停机。

M0 负责把仓库、工具链、环境、测试资产/runner、夹具、数据与证据工具调整到可工作状态；这些可逆工程问题不再前移成章程门票。

## 要做的事情

1. 先验证规格物化覆盖报告与真实动作授权；五项冻结闸未全绿 → 退回 T<规格冻结>，授权缺口 → 请用户补权；不得以环境或 runner 尚未就绪为由拒绝写章程
2. 按 `{{goal 章程 skill}}` 写章程，落 `_shared/T{n}-goal章程.md`（**≤100 行，硬上限**）
3. **切片**：按最终真值切片 + 用例矩阵切里程碑，要素表一行一片。判失败：**任一切片不能独立编译或独立验证 → 重新切**
4. **停机清算 + 收自愈清单**：按 `AI_AUTO / PRE_GOAL / CANDIDATE_DEPENDENT / LONG_LATENCY_EXTERNAL` 分类密钥、登录、平台和真实设备事项，产出 `_shared/T{n}-goal启动服务单.md`；章程拍板前清算 `PRE_GOAL`，合并候选依赖用户窗口。环境、runner、依赖、部署和证据适配等可逆工程问题仍全部授权 goal 自愈
5. **扫测试套件里硬编码的外部端点**，据结果写「禁止段」
6. **（风险触发或用户显式要求时）** 同一章程对象/基线只跑一次 `{{评审 skill}}` 红队四问；按裁决整改后调 `{{封闭验收 skill}}`，本工具原生子线程检查原 A/B/C/D 项、主线程逐条裁决，`PASS` 后关闭，禁止 R2/R3
7. 章程交用户拍板
8. **（拍板之后，本阶段最后一步）生成 goal 启动物**，按 `{{goal 章程 skill}}` §13.3～§13.5 产出**一条 `/goal` 完成条件**（四段：开工指令 / 完成条件 + 举证义务 / 关键约束 / 四类出口；典型 600–1200 字符，上限 4000）。**不要再另写一份「会话启动提示词」**——条件既是 evaluator 的判据又是首轮指令，拆两块 = 双份真值 = 必漂移；总控三要素承载在条件内。逐段取料照 §13.4 的表，别自由发挥。写完**回写进 `T<goal 执行>-goal执行.md` 的「会话启动提示词」段**（标题保持原名、其后紧跟代码块，否则总控脚本抓不到）——这是本阶段唯一被授权的跨子任务写入，**只准写这一段**
   > **必须拍板后做**：原料全部来自终版章程，章程还在改就写它 = 猜；若触发红队，必须等整改完成再生成

## 不做什么

- 不写产品代码或测试资产；但章程必须明确授权 goal 在冻结语义不变时创建/修复测试、runner、夹具、环境适配与证据工具
- 不扩大上游真实动作授权；目标环境、精确动作、目标对象、费用上限、副作用范围必须逐项继承，新增动作一律请求补权而不是在章程自批
- 除下游 `T<goal 执行>-goal执行.md` 的「**会话启动提示词**」一段外，**不写入任何其他子任务的文件**——那一段是本阶段唯一被授权的跨子任务写入（见「要做的事情」第 8 步），其余照总控单子任务边界执行
- **不在章程里发明规则**：「硬门」「死亡线」「必须审批」一律只是执行建议，不具停机权；**死亡线是封闭清单，无权新增**
- **不给下游新增闸门**（反棘轮）
- **不放宽 ≤100 行上限**：写不下是切片切大了或话说啰嗦了。实测放不下 → 报实际行数给用户裁决，不自行调整

## 风险与注意事项

- **B（必卡路径）是四问里最重要的一问**：A/C/D 找的是"边界太松"，**B 找的是"边界太紧"**。实践中绝大多数卡死来自 B，而所有评审都只在找 A/C/D
- 「必须做但章程没授权」**不是停机理由，是章程写漏了**——正是 B 该抓的
- 切片不能独立验证 = goal 断点续跑时**根本没有断点**
