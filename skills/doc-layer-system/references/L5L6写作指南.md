# L5/L6 写作指南 + 模版 + 金样板

> 本文件是 `doc-layer-system` §5.5（L5 客户端实现规约）/ §5.6（L6 服务端实现规约）的**配套操作手册**。
> SKILL.md 说"是什么"，本文件说"怎么写、长什么样"。规范本体的真值在 SKILL.md，本文件不与之冲突。
> 通用、不含任何具体项目内容；项目特定的路径/编号/阈值见各项目的 docs-writing-guide 补丁。

---

## 1. 先记住一句话

**L5/L6 是"重大决策的锁定层"，不是代码的说明书。**

它存在的唯一理由：把**人已经拍板、但 AI 施工时可能会自己改掉的决策**写下来锁住。人读它来验收，AI 读它来施工——**两边都得看得懂**。

如果一份 L5/L6 文档写出来人读不进去，它就已经失败了，无论它多"全""准"。

---

## 2. 什么算"核心业务链路"——决策风险试金石

不要问"这个流程大不大、重不重要"，要问这一句：

> **「不写下来的话，一个有能力的 AI 在施工时，会不会做出一个看起来合理、但和团队已拍板结果不同的选择？」**

- **会** → 这是核心业务链路/决策点，**进** L5/L6。
- **不会**（只有一种合理写法）→ **不进**，代码自由。

### 2.1 两种形态

| 形态 | 是什么 | 后端例子 | 前端例子 |
|---|---|---|---|
| **决策点** | 一个有多种合理实现、团队选了其中一种的技术/业务取舍 | 批量查 vs 循环查库；要不要缓存、缓存边界与失效；事务边界放哪；同步 vs 异步；幂等怎么保；并发怎么处理 | 状态管理粒度；缓存一致性；并发更新处理；错误重试/降级策略；乐观更新与否 |
| **复杂业务编排** | 多步骤流程，其"步骤顺序 + 每步为什么 + 关键取舍"本身就是被锁定的决策 | 下单→扣库存→支付→回滚的编排与补偿；多源数据去重合并 | 多步表单/向导的状态流转与中断恢复 |

### 2.2 什么不算（不要写进来）

纯 CRUD、纯字段透传、纯 DTO/VO 转换、标准增删改查、只有一种合理写法的操作。这些进了文档只会稀释信号、增加腐烂面。

### 2.3 判定速查

| 候选内容 | 进 L6/L5？ | 为什么 |
|---|---|---|
| "订单列表用游标翻页，游标取 createTime" | ✅ 进 | 游标设计是决策点（AI 可能用 page/pageSize，或漏掉复合游标导致漏数） |
| "按 id 查一条记录返回" | ❌ 不进 | 标准操作，只有一种合理写法 |
| "同一第三方账号被多人授权时，按 providerId 命中后拒绝跨用户覆盖" | ✅ 进 | 这是安全决策，AI 不知道就会写成静默覆盖 |
| "Service 把 Entity 转成 VO" | ❌ 不进 | 纯转换，代码自由 |
| "支付流水写入放在订单写入的同一事务内（强一致，代价是流水失败会回滚订单）" | ✅ 进 | 事务边界 + 取舍，AI 可能拆成两个事务 |

## 3. 海拔规则（治"人看不懂"的根药）

每条核心链路只描述到**决策/意图海拔**，绝不下沉到代码海拔。

**一句判定**：*"如果这句话删掉、读者直接看代码反而更准，它就超标了。"*

| ✅ 决策海拔（要这个） | ❌ 代码海拔（禁止） |
|---|---|
| 说**做了什么决策、为什么、放弃了什么** | 复述代码：A 类调 B 类、B 类再调 C 类 |
| 用精炼语言 + 表格 + 图 | 贴代码、伪代码、方法签名 |
| 每条至多一个轻量代码锚点（类名/模块名）供定位 | 满篇 `文件:行号` 引用 |
| 直接陈述结论 | 逐句加"证据/状态/置信度"尾注 |

---

## 4. 表达形式与禁列（强制）

**只用**：精炼自然语言、表格、图（流程图/状态图/时序示意，文字版 ASCII 也可）。

**禁止出现在 L5/L6 正文**：
- ❌ 代码片段、伪代码
- ❌ 逐方法实录（"X 调 Y，Y 再调 Z"式的代码复述）
- ❌ 逐句证据尾注（`证据：... | 状态：... | 置信度：...`）
- ❌ 每条结论的"状态/置信度"标注
- ❌ 漂移登记 / 缺口登记 / 技术债清单 ←（这些是真东西，但归**独立技术债登记文档**，不进 L6 正文）
- ❌ `文件:行号` 满天飞（每条最多留一个类名/模块名锚点）

> 这些被禁的东西大多是**反推提取期的工作脚手架**——可以在草稿/工作底稿里用来帮自己定位，但**最终文档必须把它们清掉**。

## 5. 模版骨架

### 5.1 L6（服务端）固定章节

```
# {域名}（L6 服务端实现规约）

> 层定位 / 范围边界（引用 06-00 架构规范，不重复全局约定）

## 1. 架构宪法（本域）
   包结构与分层落点、类命名、本域禁止模式（用表/图，不贴代码）

## 2. 技术选型（本域特有）
   本域用了什么、为什么这么选（全局选型引用架构规范）

## 3. 核心业务链路（逐条，决策风险轴）
   ### 3.1 {链路名}
     - 一句话意图
     - 步骤（精炼语言或流程图）
     - 🔑 决策点：选了什么 / 放弃了什么 / 为什么
     - 代码锚点：{类名或模块名}
   ### 3.2 {下一条} ...

## 4. 领域状态机（如有）
   状态图 + 对外投影映射表（→ L3 枚举）

## 5. 定时任务（如有）
   名称 / 频率 / 业务意图（表格）

## 6. 外部依赖（如有）
   依赖方 / 交互模式 / 失败处理策略（表格）
```

**禁列章节**（不要建这些节）：证据与置信度、漂移登记、事实缺口、逐方法调用链。

### 5.2 L5（客户端）固定章节

把上面的「包结构」换成「脚手架/目录与分层」、「领域状态机」换成「状态管理方案」、「定时任务」换成「路由树」，其余同构。核心仍是「§3 核心业务链路（逐条，决策风险轴）」。

## 6. 金样板

### 6.1 决策点条目——正确写法（短、prose+表、锁死取舍）

> **3.4 订单列表翻页**
>
> 意图：按时间倒序分页拉用户的订单列表。
>
> | 决策点 | 选定 | 放弃 | 为什么 |
> |---|---|---|---|
> | 翻页方式 | 游标翻页（游标=上一页末条的开始时间+id 复合键） | page/pageSize | 偏移翻页在并发写入下会重复/漏行；复合游标避免同一时间戳跨页漏数 |
> | 排序键 | (create_time DESC, id DESC) | 仅 create_time | 单键在时间戳碰撞时不稳定 |
>
> 🔑 施工红线：游标必须带 id，不能只带 create_time（只带 create_time 会在同时间戳跨页时静默漏数）。
> 代码锚点：`OrderQueryService`

注意：**没有一行代码，没有 `文件:行号`，没有置信度尾注**。但 AI 拿到这条，就不可能把它写成 page/pageSize 或单键游标——决策被锁死了。这就是 L6 该有的样子。

### 6.2 反面教材——典型的"代码法证报告"写法（禁止）

下面这种是冷启动反推最容易产出的、**必须避免**的写法：

> ~~`OrderQueryBiz.listOrders`：1. 入参 `beforeTime`（毫秒时间戳游标，UTC）+ `limit`（默认 10，`@Min(1)`/`@Max(50)`）。`beforeTime` → UTC `LocalDateTime`。2. `OrderQueryService.listBeforeTime(userId, beforeDate, limit)`（**三参**；可见状态白名单在 Service 方法体内从 `OrderStatusPolicy.visibleStatuses()` 注入）→ `OrderDao.selectSummaryByUserBeforeTime`，SQL `WHERE user_id=? ...`。3. `hasMore = (返回条数 == limit)`……~~
> ~~证据：`OrderQueryBiz.listOrders`、`OrderMapper.xml`（selectSummaryByUserBeforeTime）| 状态：机械提取 | 置信度：高~~

为什么是反面教材：
- 它在**复述代码**（哪个类调哪个方法、几个参数、SQL 长啥样）——读者不如直接看代码。
- 它把**最重要的决策**（为什么用复合游标、漏数风险）埋在细节里，甚至没说清。
- 满是 `@Min`/`三参`/`证据尾注`——代码一改全错，**必然腐烂**。
- 人读到第三行就放弃了。

**同一个链路，6.1 用 8 行锁死了决策，6.2 用 20 行复述了代码却没锁住决策。** 这就是差别。

## 7. 自检清单（写完一份 L5/L6 后逐条过）

- [ ] 每个进文档的条目都通过"决策风险试金石"——拿掉它 AI 真的会裁错？
- [ ] 纯 CRUD/透传/转换**没有**混进来。
- [ ] 全文**没有**代码、伪代码、逐方法调用链。
- [ ] 全文**没有**逐句证据尾注、状态/置信度标注、漂移登记。
- [ ] 每条核心项至多一个代码锚点（类名/模块名）。
- [ ] 发现的 bug/漂移/技术债已挪到独立技术债登记文档，不在正文。
- [ ] 一个没读过代码的人，能靠这份文档看懂"这个域怎么设计的、哪些地方不能乱改"。
