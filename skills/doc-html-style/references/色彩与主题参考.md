# 色彩与主题参考

> **这是起点示例，不是强制调色板。** 照抄下面整套色值等于又做了一个模板——请只借用"按语义轴命名 token""浅深两套都要单独核对对比度"这两个方法，自己定当次文档真正需要的语义轴和具体色值，然后用 `scripts/check_contrast.py` 自己重新核一遍，别直接信这份文档里的数字（这套颜色变了你就要重算）。

## 示例 token 集（三个语义轴：正文/次要文字、状态、类别）

```css
:root{
  --bg:#f7f8fb;        --surface:#ffffff;
  --ink:#1b2333;       --ink-soft:#5b6579;
  --status-done:#1a7f5a; --status-doing:#b4780a; --status-blocked:#c23b3b;
  --cat-a:#3a5aa8;     --cat-b:#8a4ec2;
  --on-status:#ffffff; /* 徽章上叠加的文字颜色，浅色模式下用白字 */
}
@media (prefers-color-scheme: dark){
  :root{
    --bg:#14171f;        --surface:#1d212c;
    --ink:#e6e9f0;       --ink-soft:#9aa3b5;
    --status-done:#3fd694; --status-doing:#e0a83a; --status-blocked:#f0685f;
    --cat-a:#7fa1e8;     --cat-b:#c99ce8;
    --on-status:#14171f; /* 深色模式下状态色变亮了，徽章文字要跟着翻成深色，见下方教训1 */
  }
}
:root[data-theme="dark"]{ /* 值同上一层深色变量 */ }
:root[data-theme="light"]{ /* 值同最上层浅色变量 */ }
```

徽章类组件（`.verdict`/`.tag` 这类背景色=状态色、文字叠在上面的元素）文字颜色必须写成 `color:var(--on-status)`，**不能写死 `color:#fff`**——下面"两条教训"里第1条就是在讲这个 token 为什么必须存在。

## 实测对比度（`check_contrast.py` 跑出来的真实数值，不是估的）

正文阈值 4.5:1，大字/图形（徽章文字、图标）阈值 3:1。

| Token | 浅色下"文字-背景"组合 | 对比度 | 判定 |
|---|---|---|---|
| `--ink` on `--surface` | #1b2333 / #ffffff | 15.73:1 | 通过（正文） |
| `--ink-soft` on `--surface` | #5b6579 / #ffffff | 5.86:1 | 通过（正文） |
| 白字 on `--status-done` | #ffffff / #1a7f5a | 4.97:1 | 通过（正文，压线） |
| 白字 on `--status-doing` | #ffffff / #b4780a | 3.73:1 | **只过大字/图形阈值，正文不合格** |
| 白字 on `--status-blocked` | #ffffff / #c23b3b | 5.28:1 | 通过（正文） |
| 白字 on `--cat-a` | #ffffff / #3a5aa8 | 6.55:1 | 通过（正文） |
| 白字 on `--cat-b` | #ffffff / #8a4ec2 | 5.32:1 | 通过（正文） |

| Token | 深色下"文字-背景"组合 | 对比度 | 判定 |
|---|---|---|---|
| `--ink` on `--surface`（深色） | #e6e9f0 / #1d212c | 13.23:1 | 通过 |
| `--ink-soft` on `--surface`（深色） | #9aa3b5 / #1d212c | 6.34:1 | 通过 |
| 白字 on `--status-done`（深色） | #ffffff / #3fd694 | 1.87:1 | **不合格** |
| 深色字 on `--status-done`（深色） | #14171f / #3fd694 | 9.60:1 | 通过，改用深色字后达标 |
| 白字 on `--status-doing`（深色） | #ffffff / #e0a83a | 2.14:1 | **不合格** |
| 深色字 on `--status-doing`（深色） | #14171f / #e0a83a | 8.38:1 | 通过 |
| 白字 on `--status-blocked`（深色） | #ffffff / #f0685f | 3.07:1 | 只过大字/图形阈值 |
| 深色字 on `--status-blocked`（深色） | #14171f / #f0685f | 5.84:1 | 通过，更稳 |

## 两条从实测数值里抽出来的教训（不是拍脑袋规则）

1. **深色模式下状态色通常会变亮更饱和**（`--status-done` 从 `#1a7f5a` 变成 `#3fd694`），这时如果徽章文字还是沿用浅色模式的白字，对比度会从"通过"直接掉到"不合格"（1.87:1）。深色模式下这类高亮徽章往往要把文字从白色换成深色（`#14171f` 这类接近背景色的深色）才能重新达标——**不能只翻转背景色、文字色照抄**，两个模式要分别核一遍。这也是为什么示例 token 集里专门有个 `--on-status`（而不是在组件 CSS 里写死 `color:#fff`）：徽章文字颜色本身也要跟着主题切换，`references/形态标定样例.md` 里的决策表和QA卡片片段就是这么写的。
2. **`--status-doing`（进行中/警示色）这类中等饱和度的暖色，天生就容易卡在"只过大字阈值、不过正文阈值"的边界**（浅色模式白字 3.73:1）。这种颜色适合只用在徽章/标签这种大字场景，不要直接拿去当小号正文字的颜色。

这两条不是"照抄结论"，是"照抄检查方法"——换一套色值后，用同样的方法重新跑一遍 `check_contrast.py`，让脚本告诉你新颜色算不算数，别凭这份文档里的旧数字下结论。
