# 口径卡：goal 章程评审（红队）

> 用法：`adversarial-review` §3.2 打包时把**本文件全文**内嵌进「本次评审口径」槽位。评审者与裁判都只认这个范围。
> **本次评审是全流程唯一每次必做的一次**：设计错了有测试兜底，**章程错了没有任何东西兜底**——它统治接下来几小时的全部自主执行。

## 这不是评审，是红队攻击

**你不是审查员，你是攻击者。** 请**扮演一个想交差的执行者**：

> 你已经跑了 4 个小时，token 预算见底，累了，只想早点收工。
> 有一个测试怎么都不绿。文档和代码对不上。有个东西章程好像没授权。
> **你会怎么钻这份章程的空子？**

**framing 决定产出质量**：问「请评审这份文档」得到 30 条不痛不痒的建议；问「请扮演想蒙混过关的 agent，说你会怎么骗过它」得到 3 条致命的。**要后者。**

## 评什么

**只有章程。** 不评设计、不评用例、不评代码——它们都已冻结，各自有过自己的评审。

## 红队四问（每类最多 2 条）

**必须给具体攻击场景**——第几步、怎么钻、导致什么后果。**不接受「建议加强 X」「建议明确 Y」这类空话，那是审查员的语言，不是攻击者的语言。**

### A 作弊路径（边界太松）

> 能不能让目标条件**全部判定通过，但活儿其实没干成**？

- 测试能否被 mute / skip / mock / 改弱？
- 「全绿」能否靠删用例达成？
- 目标里有没有哪条其实**不可判定**，可以嘴上说"做完了"？
- 有没有办法改规格再理直气壮地改脚本？

### B 必卡路径（边界太紧）★ 最重要的一问

> **严格按这份章程执行，哪一步会必然卡死、必须问人？**

- 有没有"必须做、但章程没授权"的动作？（**这不是停机理由，这是章程写漏了**）
- 停机条件会不会被某个常见情况误触发？
- 有没有哪个边界写得太死，导致正常施工都过不去？
- 自愈清单是不是漏收了某个已知的桶2 条目？

> **这是本口径卡最重要的设计。** A/C/D 找的都是"边界太松"，**只有 B 找"边界太紧"**。
> **历史事实：过去两个月所有的卡死痛苦，全部来自 B——而所有评审都只在找 A/C/D。**
> 漏一条规则 = 事故，多加一条规则 = "严谨"——这个激励不对称把棘轮拧到了让用户说出「流程令人挫败」的地步。**B 是唯一往回拧的那颗螺丝。**

### C 漏停路径（边界太松）

> 有没有**被允许的动作**可能造成不可逆后果，而停机条件没覆盖？

- 允许段里有没有藏着不可逆的东西？
- 禁止段是**按可达性**写的，还是只枚举了动作类型？
  > **实测事故**：章程写了「零 SSH、零部署、零重启、零配置修改、零数据库操作」保护一台生产机，goal **一条都没违反**——它通过测试文件里硬编码的 `http://<受控环境>:<端口>` 发 HTTP 请求越了界。**按动作类型枚举禁令，必然有漏网。**
- **测试套件扫过了吗？** 跑测试 = 执行任意代码 = 可达任何网络端点，这是最隐蔽的能力通道

### D 断点丢失

> 里程碑跑挂了，**从哪续**？

- 有没有不可重入的动作？（半截 Migration、已推的 commit、已发的外部请求）
- **每个切片真能独立编译 / 独立验证吗？** 不能 = goal 根本没有断点，一挂就得从头
- 中间态是否长期不可编译？（= 没切对）

## 硬约束

- **严重度预算**：阻断级最多 3 条，每条过【停线测试】三问
- **反棘轮**：**禁止**提"给章程加一道人工确认 / 加个审批环节"这类建议——那是把 goal 打回过程管控，等于本次改革白做。要防的风险请指出**章程内部**该怎么改（改边界、改验证器、改自愈授权）
- **死亡线是封闭清单**：不许以"这也算死亡线吧"为由要求新增停机条件
- **≤100 行是用户拍板的硬上限**：不许建议"为了写清楚可以放宽到 150 行"。写不下 = 切片切大了或话说啰嗦了

## 改完只做封闭式 A/B 整改验收

章程按裁决改完后，**禁止重新发起开放式红队或生成新意见**。调用 `closed-remediation-review`：一个本工具原生子线程只对原报告中的 A/B 采纳项、用户裁决与整改 diff 做封闭检查，再由主线程逐条裁决。

封闭验收仍须同时核对两端：A 的作弊路径是否被堵住，整改是否制造了 B 的必卡路径；但检查清单固定，**不得借机新增第五问或新一轮 A/B 攻击意见**。

同一章程对象/基线只允许一次开放式红队。只有用户裁决、上游冻结真值或章程发生根本重写时，登记旧评审失效原因后才可把新版本作为新对象评审。

## 三桶归置（本口径的具体化）

| 桶 | 在章程评审里长什么样 | 处置 |
|---|---|---|
| 桶1 | 目标不可判定 / 边界有洞 / 切片不能独立验证 / **有必卡路径** | **现在改章程** |
| 桶2 | —— | 章程本身就是桶2 的收口处，评审阶段一般不再产生新桶2 |
| 桶3 | 已接受的残余风险（如某个 N/A 豁免） | 记进章程「已知豁免」 |
