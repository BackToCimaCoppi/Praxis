# goal-charter

> 把一段本来要靠人逐工序把关的施工，压成一份「目标 + 验证器 + 边界 + 自愈清单」的执行契约——人只在拍板章程和终点验收各出面一次。

## 这是什么

一份写给自主执行体的**候选件生产契约**。它规定：完成时什么事实为真、用什么证据证明、哪些事可以自己干、哪些绝对不许碰、卡住了什么情况才准来问人。

写完之后交给自主执行模式一口气跑到底，中途不汇报。**但执行体无权宣布整个任务完成**——它只能跑到"精确候选可供独立验收"，最终由候选终审判定。

- **管**：章程写什么、写多长、边界怎么定义才防得住、验证器怎么设计才不能作弊、章程如何交接给自主执行开关。
- **不管**：设计决策怎么做（`lightweight-design`）、用例怎么写（`test-case-design`）、层定位与管辖范围（`doc-layer-system`）、总控子任务怎么编排（`task-control-doc`）、具体命令（项目执行 skill）。

## 解决什么问题

让 AI 长程自主干活，会同时撞上两堵墙：

**一堵是过程管控的成本墙**。传统做法是每道工序设一个闸：设计审一次、蓝图审一次、代码审一次、测试审一次、交付审一次。每个闸都要人出面，于是"让 AI 自己跑完一件事"实际变成"每十分钟被打断一次"。更糟的是闸门数量只增不减——漏一条是事故、多加一条叫严谨，于是每次复盘都往上加闸，最后流程比工作本身还重。

**另一堵是放手之后的失控墙**：

- **目标写成动作**："开发好代码、确保符合规范"——执行体会永远"在做"而不"做完"。
- **最容易漏的那条目标**：代码写完了、测试过了、文档也齐了，但**从没提交过**。目标里没写"已提交、工作树干净"，它就真的不会提交，成果以脏工作区形态裸奔。
- **边界靠动作枚举**：写了"不 SSH、不部署、不重启、不改配置、不碰数据库"来保护生产环境，结果执行体一条都没违反——它通过测试文件里硬编码的地址发了 HTTP 请求。**按动作枚举禁令，必然有漏网。**
- **reward hacking**：不去干活，去把验证器搞绿。改断言比改代码容易得多。
- **只有两个出口**：跑完，或停下来问人。当执行体证明上游规格真的错了时，它只能二选一——硬改代码绕过（灾难）或停机卡住（卡点）。

## 为什么这么设计

- **结果管控取代过程管控**：人在起点拍板一次、终点验收一次，中间靠**可判定的验证器**加边界。判断标准就一句：*这件事会改变业务结果吗？会造成不可逆后果吗？* 都不是 → 授权它自己干，记日志。**打断用户的成本远高于一次可回滚的自愈。**
- **章程无权铸造规则**：章程里写的"硬门""死亡线""必须审批"一律只是执行建议，不具停机权；死亡线是项目级文档里的封闭清单，任何人无权新增。这条是反棘轮的核心——没有它，章程会变成新一代闸门的孵化器。
- **实例 ≤100 行是物理上限，不是建议**：长文档不是一天长成的，是每轮评审垫一点垫出来的，垫到最后自己跟自己打架、把下游炸掉。物理上限比自觉可靠。上限由用户拍板，执行者无权移动，**松紧皆然**。
- **目标必须是「完成时什么为真 + 什么证据证明」**：动作没有终点，事实有。
- **边界按可达性写，不按动作枚举**：能力边界比指令边界强一个数量级——**做不到 ≫ 不许做**。首选物理隔离（禁区网络不可达、生产凭据不在场），次选按可达性写禁令（"不得以任何方式访问某端点，含 HTTP、SDK、测试夹具、第三方回调"）。启动前必须扫测试套件里硬编码的外部端点：**跑测试 = 执行任意代码 = 可达任何网络端点**。
- **第三个出口：回炉**：证明上游规格错了 → 带证据终止本次执行 → 退回设计步重来。停机是原地等答复后继续，回炉是本次作废。没有这条路，执行体只能在灾难和卡点之间选。
- **防作弊的不变量不是"脚本不变"，是"脚本的断言集合 ⊇ 规格的断言集合"**：脚本是规格的翻译，翻译可以修但不能删原文。所以哈希锚在规格上（且规格产自执行体够不着的地方），不锚在脚本上——锚脚本必然死锁。
- **红→绿翻转只暴露不阻止**：一个测试从红变绿，是改代码变的还是改脚本变的，记进飞行日志供验收时逐条看。**能暴露就够了，阻止才会死锁。**
- **执行内部禁止跑对抗评审**：对抗评审引入循环外的观点——场景不同、上下文不同，产出的是噪音。内部只能是闭环内的自审 + 机器检查器。**能做成检查器的不要做成评审**：检查器每轮免费跑、确定、即时；评审一次性、主观、会漏。
- **章程本身必打一次开放式红队**：它是唯一没有下游兜底的产物。红队四问里有一问专门找"边界太紧"——因为其余三问全在找"太松"，没有这一问，红队本身就是棘轮。整改后走封闭验收，禁止自动第二轮。

## 怎么用

**触发场景**：规格冻结之后、施工之前；或任何"我要它一口气跑完、别每隔十分钟问我一次"的长程自主执行；也用于给已跑偏的执行重定边界。

**章程固定 8 节**：目标（可判定终态）/ 里程碑（= 施工切片，要素表一行一片）/ 权限边界（允许 + 禁止）/ 停机条件（白名单四条）/ 回炉出口 / 已知豁免 / 文档动作清单 / 飞行日志与候选交接面。

**目标怎么写**：

| ❌ 动作 | ✅ 可判定终态 |
|---|---|
| 制作好测试脚本，确保符合用例 | 脚本断言集合 ⊇ 冻结用例规格的全部断言，逐条对账表可查 |
| 开发好代码，确保符合规范 | 检查器全绿，零违规 |
| 部署，跑通所有测试 | 候选部署到具名环境，矩阵全绿且测试未被削弱 |
| **（最常漏）** | **候选已提交到指定分支，工作树干净，commit/tree SHA 与证据清单已冻结** |

**里程碑 = 断点续跑的锚，不是审批关卡**。切片之间零人工闸门。判失败标准：任一切片不能独立编译或独立验证 → 重新切。**切片不能独立验证 = 根本没有断点。**

**停机白名单只有四条**：命中死亡线业务规则要变 / 凭据找不到（问位置，不猜）/ 缺陷修复没有唯一低风险答案 / 同一失败点连续三次修复无效。除此之外不停机。

### 最后一步：章程 → 启动开关

章程是**给人读的契约**，自主执行开关是**让它自己跑的指令**。交接做不好，章程写得再好也只是被人手动执行一遍。三个机制事实决定了怎么写：

1. **完成条件有字符上限，塞不下 100 行章程** → 条件必须**指针化**：指向章程文件，不复制内容。
2. **判定器不跑命令、不读文件**，只看对话里已出现的内容 → 每条终态必须转译成**可观测**形式并写明举证义务："检查器**已在本对话执行且输出已贴出**"，而不是"检查器零缺失"。否则要么无限续轮（做完了但没贴证据），要么假绿收工（嘴上说通过了）。
3. **条件不成立就自动续轮，不交还控制权** → **停机出口必须写进完成条件**，否则形同虚设：执行体老老实实报告"我需要你拍板"，判定器判条件不成立，立刻把它拉回去继续跑。

所以完成条件里要把**所有出口都写成"条件满足"**：停机白名单 / 回炉 / 用户里程碑 / 已跑满 N 轮，**四类一个不能少，漏哪类哪类失效**。

启动物**只有一条**，四段：开工指令 / 完成条件（带举证义务）/ 约束（挑最致命的 3-6 条）/ 出口。典型长度几百到一千余字符，**明显偏长基本就是在抄章程**。

**生成时机固定，一步不能提前**：写章程 → 红队一次 → 封闭验收通过 → 用户拍板 → 才生成启动条件。红队整改必然改动目标和禁令段，提前写必漂移。

**常见坑**：

- **章程里自造"硬门""死亡线""必须审批"**：这是最高频的违规，也是评审棘轮的主要入口。
- **禁止段只写动作枚举**：有物理隔离手段却不用，等于把安全押在"它想不到别的办法"上。
- **把回炉混进停机条件**：两者处置完全不同，混在一起等于没有回炉。
- **用"测试脚本哈希不变"当完成判定**：自相矛盾——脚本有 bug 就得改，改了哈希就变。
- **只写扇出禁令、不写并行授权**：执行体会把本可并行的切片串行跑。**能并行却串行同样是失职。**
- **把需要用户亲自完成的外部动作写成"已知豁免"**：应该写成「用户里程碑」让执行体停下来等，否则其下游所有真实链路验证注定只能是模拟的。
