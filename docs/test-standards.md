# test-standards

> 回答三个问题：这次改动必须测什么、测到什么深度、什么情况下不许交付。

## 这是什么

测试三件套的第一层——**规范层**。它不写用例、不写脚本、不碰命令，只做判定：本次改动命中哪些测试面、每个面的最低断言深度是多少、数据怎么准备、什么条件下必须阻断交付。

三件套的分工：

```
test-standards ────── 测什么、测多深、什么不许交付（本 skill）
      ↓
test-case-design ──── 写成可冻结的用例规格（断言、数据、追溯）
      ↓
test-execution-router ─ 路由到项目执行 skill、收证据、分类失败
```

- **管**：测试矩阵、断言深度下限、数据策略选型、自动化与手工的边界、交付阻断条件。
- **不管**：具体命令、账号端口、脚本写法、项目工具细节（归执行层）；具体用例怎么写（归用例层）。

## 解决什么问题

在 AI 主导的开发循环里，测试是最容易被悄悄稀释的一环，而且每种稀释方式看起来都很合理：

- **跳过测试写成"暂不需要"**：没有判定依据，"需不需要"变成随口一说。
- **断言只验证"跑通"**：接口测试只断言 `code == 0`，DB 校验只断言"查得到行"，单元测试只断言"返回非空"。测试全绿，业务语义一个都没验证。
- **自动化失败被降级成"手工通过"**：真正的失败被一句话吸收掉。
- **写链路只看接口响应**：不校验数据库终态，于是"接口说成功了"和"数据真的对"之间的缺口永远没人补。
- **视觉变化只留截图不下结论**：截图存在 ≠ 布局正确，但归档里看起来一样完整。
- **模拟结果冒充真实链路**：用替身跑出来的绿，和真连跑出来的绿，在报告里长得一模一样。

这些不是态度问题，是**缺少一个事前就把"最低要求"钉死的地方**。事后再问"测够了吗"，答案永远可以被辩护。

## 为什么这么设计

- **自动化是默认，手工是例外且要举证**：能自动化的必须自动化；转手工必须说明是工具、真机、第三方平台还是权限条件绕不过去，并附 runbook 与回传要求。把举证责任放在"想跳过"的那一侧。
- **跳过必须说明"为什么不命中"，而不是"暂不需要"**：前者是可被检验的判断，后者是不可检验的态度。一字之差决定这条规则能不能执行。
- **用「不合格断言 / 合格断言」对照表，而不是抽象要求**："断言要充分"没人反对也没人执行；"`code == 0` 不合格，断言字段值/错误码/状态变化才合格"直接可判。
- **改动范围 → 测试组合是查表，不是判断**：把"后端内部规则 / 对外接口 / 数据库写链路 / 后台页面 / 视觉"各自该跑什么固化成表。判断留给人只会漂移，查表不会。
- **阻断条件写成封闭清单**：交付闸必须是"命中任一即阻断"的明确列表，否则它会退化成"看着差不多就放行"。
- **规范层不碰执行细节，是为了让它跨项目复用**：命令、凭据、端口一旦写进规范层，这层就绑死在一个项目上了。所有执行细节推给项目执行 skill，规范层才能作为通用引擎存在。

## 怎么用

**触发场景**：功能开发或 bug 修复完成后、接口/数据库/UI/业务规则改动后、要判断"本次最少跑哪些测试"、审查测试覆盖是否足够、施工前或交付前的质量闸检查。

**流程**：

1. 对照「必选测试面」表，逐面判断本次是否命中，命中就写进矩阵，不命中要写清为什么不命中。
2. 对照「改动范围 → 测试矩阵」表选组合（必跑 + 常见附加）。
3. 选数据策略：DB 预置 / 接口造数 / 复用数据 / 人工前置——优先接口造数，因为它同时验证真实写链路。
4. 按「最低断言深度」表给每个面定断言下限。
5. 输出测试矩阵 + 数据策略 + 最低断言 + 阻断项。

**输出骨架**：

```markdown
## 测试矩阵
| 测试面 | 本次是否命中 | 原因 | 自动化/手工 | 保真度(真连/模拟) | 证据要求 |

## 数据策略
- 选择 / 理由 / 清理与隔离

## 最低断言
- 接口 / DB / UI·视觉

## 阻断项
- 未覆盖测试 / 不能自动化的原因
```

**常见坑**：

- **把"高风险改动"理解成"执行中要停下来等人审"**：鉴权、支付、用户数据删除、核心算法这类改动确实自动升级为高风险质量闸，但人工审查发生在设计拍板与终点验收两个时刻，**不是执行过程中的停机闸门**。搞混会让自主执行流程寸步难行。
- **在这一层写命令和端口**：一写就绑死项目，通用性当场归零。命令属于执行层。
- **矩阵写了但没写"为什么不命中"**：不命中的理由才是这张表的价值所在——它证明你判断过，而不是漏了。
- **模拟绿不标保真度**：真连绿和模拟绿必须分开计，模拟绿还要写明真实链路的收口去向，否则等于把风险藏进报告里。
