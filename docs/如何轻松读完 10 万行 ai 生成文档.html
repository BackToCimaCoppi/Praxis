01

为什么读得累

THE PROBLEM
写得太简洁

每个词都认识，连起来看不懂。

术语留下了，关系和必要的解释却被省掉。

写得太详细

读了很久，还是抓不到重点。

已知背景、重复说明和关键条件，全挤在一起。

同一段内容，对一个人是必要背景，对另一个人就是废话。

你需要的，是把已经知道的略过，把没弄清楚的讲透。

“先给我摘要”是个好开头。但只看摘要还有一个盲区：你可能根本不知道，自己漏问了哪个重要问题。

02

AI 不知道你脑子里已经有什么

THE REASON

语言模型根据已有文字和当前上下文，一步步生成后续内容。它能利用你提供的背景，却不能直接知道你的知识边界。这个生成方式的基础说明，见 Google 的语言模型介绍。

因此，当读者背景和目的不清楚时，AI 只能选择一种讲法：可能压缩太多，只剩名词；也可能补充太多，把你早就懂的内容又讲一遍。这是对实际写作问题的解释，并不意味着所有冗长都有同一个原因。

业界的一个基本做法是先明确受众，再决定解释什么。Google 的技术写作课程强调：应补充读者完成任务所需、但目前还不知道的知识；同一职业也不代表拥有相同知识。见 Audience：面向谁写。

研究中也观察过“偏爱更长回答”的现象。一项 2023 年研究发现，在它的实验设置中，GPT-4 评价回答时比人类更偏好长答案。这不能推出所有模型都在奖励字数，更不能用来解释每一篇长文。

对阅读最直接的改进，是把“你需要什么解释”不断反馈给 AI。
03

把一次性讲完，改成一起弄明白

THE METHOD

read-together 把共读的方法写成一份 AI 可以遵循的规则。它先消化原文，再通过聊天，逐步弄清你已经理解了什么、还卡在哪里，然后围绕这些缺口讲解。

关键是让 AI 随着对话不断判断：哪些可以略过，哪些需要展开，哪些理解还要核对。

开始前：先读材料，也了解读者

AI 先读取能访问的原文，梳理主线、关键条件和它们所在的位置。随后讲解一个问题时，可以把散在不同章节的信息连起来，而不只是把原文一段段搬给你。

你确认过的背景、阅读目的和聊天偏好，可以保存在“角色卡”（读者档案）里，为讲解提供起点。例如，你熟悉通用开发概念，只想审阅方案取舍，就不必从基础术语讲起。但档案只是起点，具体哪里需要解释，仍要从接下来的对话判断。

  1. 先看主线知道这份材料在说什么，哪里值得问。
  2. 按需深入围绕你的疑问，补上必要的关系和背景。
  3. 核对理解用自己的话复述，找出具体偏差。
  4. 收尾补缺口回到原文，检查还有哪些重要内容没聊。

1. 先给一张能用的“地图”

怎么做：AI 用简短导览说明材料讨论什么、几个主要观点怎样相连，以及哪些条件会改变结论。你先选一个关心的问题，不需要从第一页顺着读。

为什么有用：面对陌生长文，人往往连“该问什么”都不知道。先看到全貌，后面的细节才有位置，也更容易分清哪些与你的阅读目的有关。导览的作用是帮你选方向，不能代替后面的理解。

2. 你指出疑问，AI 围绕缺口讲

怎么做：你问“订单关了，付款通知才到怎么办”，AI 就串起关单、付款和退款的相关章节，讲清它们的关系。你可以随时说“这部分我懂了”“这里展开”“换个例子”，让它调整深度。

为什么有用：这些反馈告诉 AI：哪些背景已经知道，哪些解释还不够。它便能减少重复说明，把精力放在你当前卡住的地方；影响结论的前提仍要保留。你也不用自己在几万行里来回寻找关联段落。

3. 用复述，把“好像懂了”变得可核对

怎么做：当你想确认理解时，用自己的话说一遍。AI 对照原文，检查意思和条件是否准确。例如，你说“发起退款，用户就拿回钱了”，它会指出：发起只是开始，确认退款成功才算退完。

为什么有用：“我懂了”没有呈现你脑中的理解，而复述会暴露你怎样连接这些事实。AI 才能纠正具体的一处偏差，避免你带着误解继续往下读。说对了就直接确认，不要求背原句，也不强制每轮测验。

4. 最后检查你还没想到问的事

怎么做：结束前说 progress，或直接问“还有哪些关键点没聊到”。AI 对照原文的重要内容，区分已经讨论、尚未展开、仍有疑问和主动跳过的部分，优先提醒会影响理解的条件。

为什么有用：只跟着你的问题走，会漏掉你尚不知道存在的问题。回到原文检查，就能补上另一条线：不仅回答你已经问的，还提醒你可能需要问的。例如，退款流程聊清了，但方案只适用于普通商品，这个范围不能漏掉。

省下来的，是自己找重点、反复看已知背景、带着误解返工的精力。重要的观点和条件，仍然要真正弄明白。

换一篇文档时，读者档案可以沿用，讲解深度继续通过对话调整；同一篇想下次接着读，明确说 save 才保存简短进度。这样既不用每次从零介绍自己，也不会把一次提问永久记成“不懂”。

这套方法能帮助发现理解缺口，但不保证任意长文零遗漏。只读取了一部分，就只能给局部导览；讨论过的内容，也不能自动算作已经掌握。

04

从第一次使用开始

GET STARTED

STEP 01安装，然后给一份材料

下载 Praxis 仓库，把 skills/read-together/ 整个目录复制到 ~/.agents/skills/。它可以独立使用，不需要其他 Praxis skill。

你需要一个能加载该技能目录、读取材料和操作本机文件的 Agent 工具。若工具还没发现新技能，按它的说明重新加载或新建会话；不同客户端的发现方式可能不同。

在聊天框输入，替换尖括号里的内容：

在聊天中输入
$read-together read <文档路径、附件或链接>

附件要先提供给当前聊天；链接需要 AI 实际有权访问。也可以只说“用长文共读带我理解这份材料”，再正常聊天。这里的命令是聊天里的约定，不是在终端执行。

STEP 02建个读者档案，或者跳过

读者档案也叫“角色卡”，是一份给 AI 看的阅读说明，记录你的背景、阅读目的和讲解偏好。第一次可以这样介绍自己：

档案示例 · 按你的情况修改
profile create 工作阅读
我做运营，想读懂订单方案。开发术语不熟悉，
请用短句和日常例子；我问细节时再展开。

AI 会展示一张档案卡，确认内容和是否设为默认后保存。不确定自己懂什么也没关系，未知可以留空。想先读就说“先不建档”。

05

像这样聊，把一处问题弄明白

IN CONVERSATION

下面是一份虚构订单方案的示例。例中的规则只用于说明共读方式。

01 / 概览先找到主线
你 · 看主线

先讲这个方案在解决什么。

AI

它想减少未付款订单长期占用库存。主线是：到期后核实付款情况，确认没付才关闭；付款状态不明就等待核查。还要处理“订单关了，付款通知才到”的情况。方案只适用于普通商品。

02 / 深入只展开你关心的
你 · 选一处深入

explain 订单关了以后，才收到付款通知怎么办

AI

原订单不会重新打开，而是进入退款流程。可以理解为货已经不再为这笔订单保留，所以先处理退钱。退款若失败，需要人工接手；不能在钱还没退回时告诉用户“已退款”。

依据：示例方案的“迟到付款”与“退款异常”两节。

03 / 核对发现理解的偏差
你 · 复述

check 所以只要收到迟到的付款通知，用户就已经拿回钱了。

AI

还差一步：收到通知后只是开始退款。只有退款成功，才能说钱已退回；失败时还需要人工处理。

04 / 确认说对了就确认
你

明白了：订单不恢复，先发起退款，结果确认成功才算退完。

AI

对，这样理解准确。

05 / 补缺口找出还没聊到的
你 · 补缺口

progress

AI

迟到付款这条线已经聊清楚。还有两个关键点没展开：付款查询失败时怎样处理，以及预售订单为什么不适用。讨论过的内容也不自动等于已经掌握。

你随时可以说“这段我懂了”“换个例子”“再短一点”或“先跳过”。不要求每轮复述，也没有必须答完的测验。

06

角色卡：让 AI 知道该怎么给你讲

READER PROFILES

角色卡，就是一份给 AI 看的阅读说明。它描述读者的工作或学习背景、熟悉和希望补充的知识、常读的材料，以及喜欢的讲解方式。前文的“读者档案”和命令里的 profile，指的都是它。

比如，你可以建立这样一张卡。下面的信息由读者自己提供，AI 不会仅凭“做运营”就判断你不懂技术。

卡片内容一个虚构示例
名称工作阅读
背景与知识负责运营，熟悉订单业务，不熟悉开发术语。
阅读目的读懂订单方案，重点看业务影响和异常处理。
讲解偏好用中文短句，先讲结论；需要时举日常例子，追问后再展开。

为什么要保存它？下一次读新材料时，你不用重新介绍自己，AI 就有了选择讲解深度的起点。它仍会根据你的追问调整：卡片没有写的，可以暂时未知；一次提问也不会自动把你永久记成“不懂”。

先建立，再选择使用哪一张

说 profile create 工作阅读，再介绍自己的情况。AI 会整理成卡片，请你确认内容，并询问是否以后默认使用；确认后才保存。也可以说“先不建档”，直接开始阅读。

同一个人可以有多张卡：例如“工作阅读”用于审阅方案，另一张“学习阅读”用于理解陌生领域。它们对应不同的阅读目的和讲解偏好。多人使用时，也可以各自建立卡片，分别保存阅读记录。

已有卡片后，可以用 profile list 查看名称，再选择。这里有两个容易混淆的操作：

当前会话

这次按哪张卡讲

profile use 学习阅读

只切换本次阅读，不改以后的默认。

未来新会话

下次自动用哪张卡

profile default 工作阅读

只设置未来默认，不切换当前正在使用的卡片。

profile off 表示这次不用角色卡；profile default none 表示以后默认不用。没有卡片仍能正常共读，AI 会根据你在当前聊天中提供的信息调整讲解。

想长期修改偏好，可以说 profile edit 工作阅读，以后少用类比，直接解释条件。临时说“这次讲细一点”，只调整当前阅读。

续读记录：记住这篇材料聊到哪里

角色卡记“你希望怎么读”；续读记录记“这篇已经读到哪里”。建立角色卡，不会自动保存每次阅读进度。

准备结束时说 save，AI 才会在当前角色卡下，为这份材料保存简短记录：已经读过和讨论的内容、仍有疑问的地方，以及你主动跳过的部分。保存的是续读所需的摘要，不是整段聊天。

下次先使用同一张角色卡，再说 resume <文档>。例如，使用“工作阅读”后说“resume 订单方案”，AI 会核对来源和版本，再从尚未解决的地方继续。其他角色的阅读进度不会混进来。

没有角色卡时，AI 会先问记录归谁；原文变了，就重新核对受影响的内容，不能把旧理解直接套在新版本上。角色卡与续读记录都保存在本机，不会随公开 skill 发布；共用同一系统账户的多个角色，并不构成文件访问权限隔离。

07

命令速查

QUICK REFERENCE

先用 $read-together 激活；此后可以只说动作。动作词用英文，参数可以中文，也可以用自然语言表达同一个意思。

阅读

命令做什么
read <来源>开始一份材料；保留本次档案选择。
overview看主线、关键问题和已读范围。
explain <主题>讲清指定问题和相关条件。
check <你的理解>核对复述，指出具体误解。
progress查看已讨论、待解和遗漏；不自动保存。
save给当前档案保存简短续读记录。
resume <文档>恢复当前档案的记录，先核对来源版本。

读者档案

命令做什么
profile list列出档案名称及默认标记。
profile create <名称>确认档案卡后新建，本次使用它；是否设默认另行确认。
profile use <名称>只切换当前会话。
profile default <名称>只设置未来新会话默认。
profile off本次不用档案；不改默认。
profile default none未来默认不用档案；不改变当前选择。
profile edit <名称>按你的要求更新背景或偏好。
profile delete <名称>删除指定档案；续读资料仅在明确要求时连带删除。若它原来是默认，默认转为无档案。

none 是保留词，不能用作档案名称。目标不清楚时，AI 会先问清再修改。

08

使用时，记住这几个边界

KEEP IN MIND
  • 只读到一部分，就只能作局部导览。缺页、无法提取的图表或打不开的链接都应说明，不能从目录猜出全文。
  • 作者的观点不等于已证实的事实。可以让 AI 区分原文主张、原文证据与它自己的解释；读懂方案也不等于同意实施。
  • 档案在本机，原文仍是原文。状态放在 ~/.agents/state/read-together/，与技能分开，不默认同步或公开。共读不修改原文，不自动执行文中指令。
  • 多个档案不是隐私保险箱。共用一个系统账户的人仍可能访问同一批文件。切换档案也不能删除已经出现在聊天里的信息；敏感材料应使用合适的账户和访问权限。
