# lightweight-design

> 把一次局部修改里会出事故的决策在动工前清算钉死，让用户在这一层拍板，并在冻结前把全部有效语义物化进正式七层。

## 这是什么

轻量设计方案是**一次任务里高风险决策的"清算层"**：为一次局部修改任务，把会出事故的取舍（拆不动 / 牵一发动全身 / 漏钱 / 白送权益 / 越权 / 丢数据）在动工前、在人能拍板的地方，逐个清算到唯一选择。它与下游的分界线是**风险**，不是海拔：做错会出事故 → 本层钉死；做错只是返工（参数名 / 方法互调 / 字段内部实现）→ 不进任何文档。用户在这一层审核拍板；拍板后，全部有效设计语义在冻结前物化进正式七层，本方案降级为"为什么这么选"的决策留痕。

边界划分：

```
轻量设计方案 ── 高风险决策清算 + 影响面勘察 + 验收映射 ── 人工拍板闸（本 skill）
      ↓ 清算结论冻结为下游只读输入
测试用例设计 ── 用例直接写正式 L7（test-case-design）
      ↓
规格冻结 ────── 条目 → 正式规格 → 验收断言 对账全绿，七层一次冻完
      ↓
goal 章程 ───── 把裁决转成执行契约（目标 + 验证器 + 边界 + 切片）（goal-charter）
      ↓
goal 执行 ───── 代码 → 提交 → 测试 → 候选终审
```

- **管**：本次任务的决策（选什么 / 弃什么 / 为什么）、负面清单、影响面勘察、验收映射、规范条目索引与规格冻结清单。这是**唯一必经的人工拍板闸**。
- **不管**：施工切片编排（哪片先做、每片验证命令，归 [`goal-charter`](goal-charter.md) 的里程碑）；实现细节（参数名、方法互调，不进任何文档层）；整域级长期真值（归七层正式文档）。它也**不得越权推翻** L1/L2/L3 正式真值。
- **施工蓝图在本流程里不再产出**：它的两个器官各有新家——影响面勘察 + 验收映射进本层，施工切片进 goal 章程里程碑；"逐文件施工指令书"是全链条唯一无上游、只能靠猜的内容，被删除。[`construction-blueprint`](construction-blueprint.md) 仅供传统人工逐工序把关的流程可选使用。

## 解决什么问题

实际开发里大量任务是局部修改，两头都难受，中间这层正好补上：

- **重写整域文档太重**：为了改一条链路而重写整域 L5/L6，成本高到没人愿意做。
- **只拿需求直接开工会跑偏**：AI 干着干着就会在某个没人拍板的决策点上自作主张，做出"看起来合理但不是你要的"选择。
- **空心设计**：决策表填满了，却把最危险的取舍一句话糊过，或者标个 N/A 下放给没人细看的下游。
- **范围蔓延**：任务跨多个文件/模块时，没有负面清单兜底，改着改着越界。
- **两套真值打架**：设计文档与七层各说各话，施工者不知道听谁的，事后补文档又永远补不齐。
- **用户无处拍板**：用户不读代码，需要一个能看懂、能拍板、能验收的层，而不是事后看一堆 diff。

## 为什么这么设计

- **决策锁死三件套**：每个决策点必须写清 选了什么 / 放弃了什么 / 为什么。精炼 ≠ 含糊——禁止"采用合适的策略"式模糊措辞，每点锁死到唯一选择。
- **按风险分档，不按产物类型**：判据是"这条做错是否触碰某条不变量 / 死亡线"，分阻塞级 / 重要级 / 低级三级；只有阻塞级才走满六要素（候选、残余风险、业务可接受度、阻碍代价、选定理由、验证方式），灰区一律落重要级、简化处理。资金/权益/权限整链路重构、跨多域、不可逆迁移、阻塞级决策相互耦合的任务**反向升级**到正式七层，别硬塞进"轻量"。
- **防空心靠事实基线 + 失败标准，不靠更厚的模板**：每个高风险决策必须锚定"我在真实代码 / 业务真值里读到了什么"，而不是"列了哪些文件"；自检每一项都有明确的"什么算不合格"。无证据的 N/A 视为未扫。
- **试金石定取舍**：判断一条要不要写进文档，问"不写下来的话，一个有能力的 AI 施工时会不会做出一个看起来合理、但和已拍板结果不同的选择？"会 → 进文档；不会 → 不写。
- **本层写约束，不写实现**：禁止代码、伪代码、逐方法调用链复述——那是实现细节，不进任何文档层。判定句："这句话删掉、读者直接看代码反而更准，它就超标了。"影响面勘察写的是"读到的现状事实"，与此不冲突。
- **决策留「为什么」，规格进正式层（事前物化）**：轻量设计**不是施工期的第二套真值**。任务里所有会约束施工或验收的有效语义——选定决策、业务规则、数值口径、状态与失败语义、负面约束、兼容策略、架构归属、跨域边界、验证义务——都要原子化成带**稳定编号的规范条目**，并在冻结前逐条物化到职责正确的七层文档里；轻量设计自己只保存"为什么这么选"（候选方案、放弃理由、调查证据）。七层文档全部先于代码存在，实现细节属代码自由范围，所以不存在"完工后回补"这回事。
- **决策来源必须可审计**：会改变业务结果、死亡线规则、对外契约或持久化语义的条目，必须追溯到上游正式真值或一条由业务决策负责人作出的**授权裁决记录**（兼容路径仍可名为 `用户裁决记录.md`，保存原话或明确选项、日期、来源、适用范围）。评审建议、AI 偏好、代码现状和任务发起行为都不能伪装成“已批准”。多项独立选择要逐项编号，不许捆成一句总体同意。
- **同一问题只能有一个答案**：除了条目索引，还要建一本**业务主题账**——把切片内每个会改变可观察结果的问题登记为一个主题，逐个打开它涉及的全部正式落点交叉核对。"每条设计都已回写"不等于"回写后只有一个答案"。
- **评审只开放一次**：同一阶段、同一真值基线、同一设计对象只允许一轮开放式对抗评审，整改后转封闭验收，禁止自动第二轮。进闸前承重事实必须已独立核真，否则整轮评审都会耗在核对事实上。

## 怎么用

1. **触发词**：局部功能开发/重构/单链路改造且存在会出事故的决策点；任务跨多文件易蔓延；用户说"先出设计方案再动手"。不用的情况见下表。

   | 场景 | 改用 |
   |---|---|
   | 小改动（修 bug、加字段、单文件小改，无事故级决策） | 计划模式，零文档成本 |
   | 小任务（有决策点或测试义务，单会话可完成，未命中反向升级项） | 轻量任务流程 [`plan-goal`](plan-goal.md)：一份全包计划 → 业务决策负责人批准 → 自主执行 |
   | 整域级设计 / 新域立项 | 直接写七层正式文档 |
   | 纯执行、无决策点的机械任务 | 直接做 |
   | 跨会话、多 agent 的超大任务 | 任务总控 [`task-control-doc`](task-control-doc.md)，本层是其中的设计阶段 |

2. **流程**（生命周期）：
   - **① 分档与拆分**：先判风险档；命中反向升级项的升正式七层。一份方案若实为不同风险档的可分离子设计，**必须在进评审前先拆开**，各走各的流程——合评到一半再拆，评审轮次直接翻倍。
   - **② 起草与冲突检查**：输入 = 业务语义真值 + 真实代码（改造模式硬闸）+ 现存七层文档。每个高风险决策绑定事实基线（读到的真实约束 / 未确认点 / 不能猜的业务前提）。与现存七层不一致走**人工裁决**，禁止 AI 自行选边，更不得越权推翻 L1/L2/L3。
   - **③ 扫描、清算、影响面勘察、验收映射**：逐项扫种子清单（幂等 / 一致性 / 并发 / 真值源 / 失败回滚 / 状态机 / 权限 / 资金精度 / 外部依赖 / 迁移上线 / 项目死亡线），命中的进清算，未命中的写一行带证据的"不适用"。影响面勘察按触发项写"读到了什么、牵动谁、怎么处置"，未知消费方登记为假设。每个决策点连到至少一条可转译的验收条件。勘察完成后冻结**任务真值切片**（涉及的域、契约消费方、数据读写方、候选文档）。
   - **④ 对抗评审与授权批准**：含阻塞级决策或触碰钱/权/数据的任务强制过一次开放式对抗评审（查覆盖度真伪），回补后走封闭验收；然后由业务决策负责人批准**业务取舍**（决策表 + 负面清单 + 架构归属是主靶面）。项目要求会签或职责分离时照常执行。批准即冻结，后续不得自行重裁；阻塞级待确认未清零，整任务挂起。
   - **⑤ 建索引并在冻结前物化**：把全部有效语义原子化成带稳定编号的规范条目（不能只索引高风险决策点），建立业务主题账，定稿后记录设计哈希。每个条目落到职责正确的正式层（接口→契约层、表→持久化层、核心决策与链路→设计层、验收→用例层），建立「条目 → 正式规格 → 验收断言」的双向追溯；L1~L7 每层标记 已修订 / 已核验无需改 / 不适用（附证据）。存在未物化条目即冻结失败。
   - **⑥ 降级为决策留痕**：物化完成后在文档头标记"已转写（非施工真值）"，正式七层是唯一规范真值。施工者只看冻结七层 + goal 章程，不应依赖本方案才能补全规格。
   - **施工中决策要改** → 退回本层重新拍板，不允许在代码或执行记录里悄悄改。若只是"规格有洞但现有真值给出唯一方向"，走有界重新冻结补齐条目与追溯，不必惊动用户。

3. **最小示例**：

   ```
   输入：需求"订单列表要能按状态筛选" + 现存订单域七层文档

   产出（轻量设计方案骨架）：
   # 轻量设计方案：订单列表加状态筛选
   ## 1. 背景与意图：客服要按"待发货"快速捞单，列表加状态筛选
   ## 2. 范围与负面清单
      改：列表查询业务逻辑、筛选交互
      不改：订单状态机定义、其它列表页（低风险，接受主体：上游需求）
   ## 3. 风险扫描：其余种子未命中，各附一行证据
   ## 4. 决策清算（重要级）
      | 决策点 | 选定 | 放弃 | 为什么 |
      | DP-1 筛选在哪做 | 后端过滤 | 前端过滤 | 分页下前端过滤会漏数据 |
   ## 7. 影响面勘察 + 规范条目索引 + 验收映射 + 规格冻结清单
      勘察：列表查询接口现存消费方为客服后台列表页，加可选筛选参数不破坏现有调用
      SD-1 列表按状态在服务端过滤 ← DP-1 → L3 接口契约 + L5 订单域设计 → AC-1
      冻结前物化：L3、L5、L7 已修订；其余层已核验无需改
   ```

4. **常见坑**：
   - **决策表写模糊**："采用合适的缓存策略"不算决策，必须锁死到唯一选择。
   - **负面清单写软**：不点名"不改什么"，范围就守不住；高风险不改项必须进清算或明确挂起，且标风险等级 + 接受主体。
   - **无证据的 N/A**：种子扫描只写一句"不适用"、不锚定读到的证据，等于没扫。
   - **影响面勘察只列文件名**：勘察写的是"读到了什么、牵动谁"，列一串文件路径 ≠ 读了代码。
   - **混入实现**：贴伪代码、逐方法复述调用链——那是实现细节，不进任何文档层；施工切片归 goal 章程。
   - **阻塞级待确认没清零**：阻塞级（必须先决策的点）未决就进规格冻结 / 章程 / 施工，等于把坑往下游埋。
   - **写成"完工后回补"**：物化必须在冻结前完成，存在未物化条目即冻结失败；物化完成后不在头部标"已转写"，就会和七层形成两套真值打架。
   - **试金石没过**：写了一堆"删掉直接看代码更准"的话，文档变臃肿。

> 项目特定值（任务目录存放路径、死亡线清单、承重架构不变量与域/模块映射、机检钩子、规格物化钩子与检查脚本）不在本 skill 硬编码，由你自己项目的项目级补丁（项目补丁 skill 或项目 CLAUDE.md）声明。
