# read-together

> 长文共读：先弄清主线，再通过聊天逐步读懂原文。

## 这是什么

`read-together` 是一份教 AI 如何陪你读长文的 skill。
它适用于设计方案、规格文档、论文和其他长篇材料。

AI 先消化可读取的原文，再围绕你的问题讲解，核对你的理解，提醒遗漏的重要条件。
你不必一段段读它搬来的原文，也不必先学一套文档管理流程。

它不修改原文，不自动执行文档中的操作，也不保证任意长文绝无遗漏。

## 解决什么问题

长文经常把已知背景、陌生概念和关键限制放在一起。
只看摘要可能漏掉条件，逐字读又很费力。

AI 也不知道你已经懂什么。要求它“简短”，可能只剩术语；要求它“详细”，又可能讲太多。
共读把一次性写完整篇，变成按你的实际理解逐步展开。

## 为什么这么设计

- 先给主线和几个关键问题，让你知道可以从哪里问起。
- 你选哪部分，就围绕它串起相关章节，只补必要背景。
- 你用自己的话复述，AI 对照原文纠正具体误解；说对了就直接确认。
- 结束前检查尚未讨论的重要内容，减少“我不知道还有什么该问”的盲区。

这几个动作各解决一层困难：导览帮助你知道该问什么，追问让 AI 调整讲解深度，复述暴露具体误解，收尾核对补上你尚不知道该问的条件。原文始终是核对依据。

读者档案也叫“角色卡”，描述一个具体的读者身份，例如“运营负责人”或“后端工程师”，并记录这个角色的知识背景、关注点和讲解偏好。AI 因此知道在给谁讲，从哪里讲起。
它可以有多个，也可以完全不用；档案不会因一次提问就把你永久标成“不懂”。

默认状态放在本机 `~/.agents/state/read-together/`，与公共技能分开。
多个档案是偏好区分，不是同一系统账户中的隐私隔离。

## 怎么用

[Praxis](https://github.com/BackToCimaCoppi/Praxis) 是一个开源 AI 技能库，把阅读、设计、开发、测试等常用做法整理成可复用的工作指南。
[read-together（长文共读）](https://github.com/BackToCimaCoppi/Praxis/tree/main/skills/read-together) 是其中一个技能，可以单独安装。

**先安装。** 打开支持本地技能、能联网和读写本机文件的 AI 工具，把下面这段话发给它：

```text
请从 https://github.com/BackToCimaCoppi/Praxis
安装 skills/read-together 这个技能。
将完整目录保存到 ~/.agents/skills/read-together/，只安装这一个技能。
请检查当前工具能否识别它；如果需要额外配置或重新加载，请告诉我怎么做。
```

也可以打开 GitHub 项目，点击 **Code → Download ZIP**，解压后把完整的 `skills/read-together/` 目录复制到 `~/.agents/skills/`。
不同工具的技能发现方式可能不同，按其说明完成配置或重新加载。普通网页聊天如果没有本机文件权限，就不能替你安装。

**再开始阅读。** 确认工具已识别技能后，在聊天中输入（不是终端命令）：

```text
$read-together read <文档路径、附件或链接>
```

第一次可以介绍背景和讲解偏好，确认档案卡后保存；也可以说“先不建档”。
之后既能用命令，也能直接聊天：

```text
overview
explain 订单关闭后才收到付款通知怎么办
check 我的理解是：订单不会重新打开，而是进入退款流程
还有哪些关键条件没聊到？
```

角色管理示例（先分别创建两张卡，再选择使用哪张）：

```text
profile create 运营负责人
profile default 运营负责人
profile create 后端工程师
profile use 后端工程师
profile off
```

创建档案先确认内容；`profile use` 只影响本次，`profile default` 只影响未来新会话。
`profile off` 仅停用本次档案，`profile default none` 才是以后默认不用。

角色卡记录你是谁、懂什么、关心什么；续读记录另行保存这篇材料读到哪里。
想下次继续时说 `save`；下次选择同一档案后说 `resume <文档>`。
没有档案时不会擅自保存到某个人名下。原文版本变了，旧理解要重新核对。
