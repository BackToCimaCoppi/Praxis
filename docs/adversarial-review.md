# adversarial-review

## 这是什么

同一对象和正式真值基线只开放一次的独立评审。触发时运行 `skills/adversarial-review/scripts/discover_bridges.py`，实时检查用户机器上的 Claude Code、Cursor Agent、Codex 三种桥接与账户模型。用户至少选择一个实际可用的桥接和模型标识；不可用桥接说明原因，不阻断其他桥接。

## 解决什么问题

固定模型名单不能代表每位用户当下的安装、登录和权限状态。评审者也容易互相污染意见，或者把建议直接变成业务决定。这里由各评审者使用同一冻结证据包，在项目根内独立只读勘察；当前主线程核证、合并和逐条裁决。

## 为什么这么设计

- 模型清单每次重查，禁用 Fast、Auto 和未经确认的替代模型。可提示高能力候选，但用户可从完整的可用列表选择。
- 最少一个模型也能完成评审。只有多个模型实际参与时才比较贡献并排名；单模型报告只写发现、局限和裁决。
- 同一 `review_id + object_hash + truth_baseline_hash` 只开放一次，整改交给 `closed-remediation-review` 的固定清单验收，防止 R2/R3 棘轮。
- 评审意见不取得规格地位。改变业务结果、接口契约或持久化语义时须有正式来源或授权裁决。

## 怎么用

说“对抗评审”。系统展示桥接状态和非 Fast 模型，请用户选择一个或多个“桥接 + 模型”（Codex 可选推理档）。选择后再次核对模型可用性，再冻结证据包，独立并行评审、主线程裁决和整改。报告记录实际模型、CLI 只读参数、独立调查账、裁决及封闭验收状态。所选模型失败时同包重试一次，仍失败让用户从刷新清单中重选，不自动换档。
