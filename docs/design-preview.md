# design-preview

> 把一个 UI 形态还原成像素级 HTML，自动弹到浏览器里，让人**对着真图**评审，而不是看文字描述或 ASCII 画。

## 这是什么

一个**沟通介质生产器**。它读页面的真值源（结构文件 + 样式文件），还原成一张自包含的 HTML 效果图，起本地服务在浏览器里弹出来，再截图确认人和 AI 看的是同一张图。

它只负责"出图 + 弹窗 + 迭代"，**不负责拍板**——设计结论由调用方写回对应文档。

- **适用**：把已有页面 1:1 还原确认现状、把拟改形态做成效果图对图拍板版式、多变体并排比对。
- **不适用**：需要可运行交互验证（长按菜单、登录链路、网络请求）→ 用平台自己的开发者工具或真机；要生成可部署的真实代码 → 那是施工，不是预览。

## 解决什么问题

聊页面形态时，AI 和人之间最大的损耗是**没有共同的视觉对象**：

- **文字描述说不清版式**："卡片上方放头像，右侧两行文字，底部一条统计栏"——十个人能脑补出十种样子，聊半天最后发现各想各的。
- **ASCII 画图更糟**：它既不精确又占篇幅，还给人一种"已经沟通过了"的错觉。
- **凭空生成器会偏离真值**：让 AI 从 prompt 直接生成一张漂亮效果图，它画的是"一个合理的页面"，不是"你项目里那个页面"。颜色、圆角、间距全是编的，拿它拍板等于拍了个不存在的东西。
- **人机看的不是同一张图**：AI 说"已经改好了"，但它没看过渲染结果。样式没生效、布局错位、元素重叠——这些肉眼一秒可见的问题，在纯文本流程里能一路蒙混到用户面前。

## 为什么这么设计

- **与代码同源，是唯一的保真承诺**：还原必须读项目里的结构与样式真值，不凭记忆画、不引第三方凭空生成器。拿不准就先读代码，涉及多形态分支就逐个确认。
- **用「舞台 + 等比缩放」免掉手算换算**：模板里放一个宽度等于设计稿基准的舞台并整体缩放，样式里的设计单位数值**直接当像素填**。禁止手动换算——换算就是引入误差的地方。
- **截图自检是硬闸**：出完图必须截一张确认渲染正常，异常就改到正常再交付。**质量的真正来源是这道闸，不是模型档位**——出图本质是"照搬结构 + 抄样式数值"的受约束转写，转写错肉眼可见（不像代码 bug 会藏），所以一道验收闸就够了，档位只影响速度。
- **默认派子线程出图**：设计推理和拍板留主线程，读源码 + 敲 HTML 是体力活，放进子线程的干净上下文，避免把主线程的设计思路挤掉。
- **弹窗归主线程做**：主线程工具已加载、本地服务常驻，弹窗只要两三个调用；子线程不必再加载浏览器工具，关键路径更短也更稳。
- **串行是默认，批量才并行**：聊单个页面时一次出一张，出完对图聊完再下一个——匹配人推敲的节奏。只有用户明说"全部预览"才并行出图拼成画廊。**不要自作主张并行。**
- **视觉等价 ≠ 运行等价**：HTML 只还原"长什么样"，交互只能静态示意。出图时要主动标注这一点，否则用户会以为交互也验证过了。

## 怎么用

**触发词**：预览设计稿、出个效果图、弹个预览、给我看看效果、还原一下页面、看看这个形态长啥样、对着图聊。

**触发后第一件事**：确认要预览哪个形态。上下文明确就直接开工，不明确就一句话问清，**不要默认**。

**四步**：

1. **定位真值源**——找到目标形态的结构文件与样式文件。已有形态照搬；新形态以同源样式为基准改，确保和现状同风格。
2. **写自包含 HTML**——复制模板作骨架，样式值照抄真值（颜色/圆角/字号/间距/投影一律不许"差不多"），填真实感数据（不要 lorem），多变体横排并标清哪个是哪个。
3. **弹浏览器**——起本地静态服务，导航到 `http://localhost:<端口>/<文件名>`，截图自检。
4. **对图迭代**——用户提意见 → 改 HTML → 刷新 → 再截图。反复到满意。

**派子线程的工单包含**：要还原哪个形态、真值源路径（结构 + 视觉，带行号或类名范围）、数据口径、设计意图（仅新形态）、存放位置、交付契约（保真红线 + 返回什么）、授权范围（只准写指定目录，禁止改源码）。

**保真红线**：

1. 单位换算只走模板的舞台缩放，禁止手动猜。
2. 视觉值照抄样式源，不许估。
3. 主动标注"交互以真机/开发者工具为准"。
4. 不引第三方凭空生成器。
5. 新增或改动的形态要标清，别让人把提案误认成现状。

**常见坑**：

- **用 `file://` 打开**：浏览器扩展受沙盒限制打不开本地文件协议，必须起本地 HTTP 服务。这是最容易卡住的一步。
- **文件名含非 ASCII 字符不做 URL 编码**：导航会失败。
- **触发浏览器模态框**：alert/confirm 会卡死扩展。纯展示页一般无此风险，但别手贱加。
- **把坏图丢给用户**：截图自检发现错位、空白、样式没生效，改到正常再交付。
- **拿预览当拍板记录**：本 skill 不记录结论，拍板后由调用方写回文档。
