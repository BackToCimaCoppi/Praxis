# doc-html-style

> 把文档写成桌面阅读优先、色彩丰富但不失控的自包含 HTML——**不套模板，套的是判断力 + 一组硬规则 + 一个自检脚本**。

## 这是什么

一套把技术文档、设计文档、业务问答、评审报告、复盘总结写成 HTML 成品的规范。它不提供骨架库让你挑一个，而是要求先判断这份文档的**形状**（读者是谁、篇幅多大、主信息靠什么承载），再决定结构与视觉投入档位。

核心差异化在色彩：目标是比朴素单色更丰富的配色，但"丰富"必须靠纪律兜底，否则直接滑向大杂烩。

- **管**：已经确定要写的内容如何组织成一份桌面优先、色彩克制而丰富、明暗皆宜的自包含 HTML。
- **不管**（明确交接出去）：手机端页面还原 → `design-preview`（那是移动端形态复刻，方向相反）；文档内嵌真实图表的配色 → 图表配色专门规范；内容该写进哪层文档、矛盾听谁的 → `doc-layer-system`。

> 注：交接对象里，图表配色与 Artifact 沙盒规则属于本库之外的外部 skill，本库不提供。缺失时按本 skill 的色彩纪律处理即可。

## 解决什么问题

把文档做成 HTML 这件事，失败方式高度雷同：

- **套模板导致所有文档长一个样**：一份三段的内部问答记录和一份对外设计文档用同一个骨架、同一套卡片、同一个 hero 区，投入档位完全没有区分。
- **"丰富配色"变成随手撒色**：这里加个蓝、那里加个橙，颜色不绑定任何语义。读者看到红色不知道是"风险"还是"已完成"——同一份文档里它可能两个意思都有。
- **暗色模式漏一半**：语义色只在浅色模式定义，切到深色模式后徽章文字和背景糊成一片。
- **对比度靠肉眼判断**："看着还行"和"达标"是两回事，尤其深色模式下状态色会变亮变饱和，白字叠上去经常不合格。
- **横向滚动条**：一张宽表格让整个页面横着滚，阅读体验当场崩掉。
- **"AI 感"反模式**：每张卡片不分主次套同样的阴影圆角、标题渐变文字、emoji 当图标堆砌、大面积紫蓝渐变背景——出现即说明设计投入不走心。

## 为什么这么设计

- **先判形状，而不是选模板**：五个问题（读者是谁 / 篇幅多大 / 主信息载体是代码还是决策表还是问答对还是时间线 / 要不要打印 / 这次投入多大精力）决定结构与视觉档位。模板会让判断力退化，判断力才是可迁移的。
- **颜色按语义轴分配**：状态轴、类别轴、结论轴——同一个轴的色相在一份文档里固定，不中途洗牌。装饰性撒色一律禁止。
- **同时出现的语义轴不超过 2–3 个**，这是防止"更丰富"滑向"大杂烩"的**唯一硬限制**。轴超过三个说明文档想表达的维度太多，该拆层级而不是继续加色相。
- **明暗主题三层 token，缺一不可**：语义色定义在根变量上 → 用系统偏好媒体查询覆盖同一批变量 → 再用显式主题属性覆盖一层保证手动切换能压过系统偏好。组件样式只准吃 token，不准写死颜色值。
- **对比度用脚本验，不靠肉眼**：每个语义色在浅色和深色模式下的"文字-背景"组合都跑一遍，不达标就回去调。特别是徽章类组件（背景是状态色、文字叠在上面）必须有专门的"叠加文字色"token——深色模式下状态色变亮，写死白字必然不合格。
- **宽内容自己滚，页面不滚**：表格与代码块各自套横向滚动容器，`body` 绝不允许横向滚动。
- **参考色板是起点不是标准**：照抄整套等于又做了一个模板，与本 skill 的立意相反。
- **仅手动触发**：不根据"写文档""HTML"这类关键词自动调用。即使内容看起来符合场景也不主动触发——把决定权留给人。

## 怎么用

**触发方式**：只在显式调用时使用。

**流程**：

1. **判形状**：过一遍五个问题，定下结构与视觉投入档位。内部小记录不必和对外设计文档一样精修。
2. **搭结构**：自包含单文件（CSS/JS 全内联，不外链）；内容区宽度定在桌面区间居中，用流式排版；长文档才加目录导航，一屏能看完的加了是噪音。
3. **配色**：先确定这份文档有哪几个语义轴，每轴选一组色相并固定；写完跑对比度自检脚本，任何一组不达标就回去调。
4. **自检**：过一遍判失败清单。

**判失败清单**（结构类）：

- 页面出现手机舞台尺寸或整体缩放（说明抄错了 skill）。
- 某个语义色只在一种模式下定义，另一种漏掉。
- 表格或代码块导致整个页面横向滚动。
- 按手机窄栏宽度设计一份桌面文档。

**判失败清单**（色彩类）：

- 某个语义色的文字-背景组合对比度不达标，仍用在正文或关键状态标识上。
- 同一种颜色在文档不同位置代表两种不同含义。
- 语义轴已超过三个还在继续加新色相，而不是拆分层级。
- 命中"AI 感"反模式两条及以上。

**常见坑**：

- **把参考色板当强制调色板照抄**：那就又变成模板了。
- **徽章文字写死白色**：深色模式下必然出问题，必须走"叠加文字色"token。
- **短文档硬加 sticky 目录**：篇幅决定要不要目录，不是越全越好。
- **凭感觉判断对比度**：脚本存在的全部意义就是不让人凭感觉。
